> 遵循 Keep a Changelog 精神，记录 github-net 每个版本改了什么。当前应用版本 `0.1.0`（单一真实来源：`main.go` 的 `appVersion`；以后建了 `wails.json` 就换成它的 `info.productVersion`，两个地方不能同时算数）。发布正文用仓库根的 `release-notes.md`，由 `scripts/gen-release-notes.sh` 从 `docs/release-notes/<版本号>.entries` 那份条目清单生成（`release-notes.md` 是生成物，不手改），格式契约见脚本头注释。

> 版本标签用 `v主版本.次版本.修订号`（如 `v0.1.0`），预览版带后缀（如 `v0.2.0-beta.1`）。出正式版时把「未发布」段的内容整理成该版本小节。两边分类不完全一样，是有意这么定的：仓库日志继续按 新增/修改/修复/删除 四类记；Release 正文按固定三组出——新增、修复、更新，其中「修改」和「删除」都并进「更新」这一组（条目动词写清，例如「删除了…」），没有内容的组只写一个「无」（英文段写 `None`），有条目按 `1.`、`2.`、`3.` 编号；版本类型不单独成行，并进标题（如「0.1.0 稳定版」）；中英各一份，形状由 `scripts/gen-release-notes.sh` 保证，条目内容要精简、准确、只写本版净变化。

- **Hosts 只读**：`internal/hosts` 落地管理区段判读（标记固定为 v1 那一对，缺端、重复、嵌套、顺序错、版本未知、区段内非法行全部识别并给出带行号的原因）与只读读取；`GetItems` 每次调用现读一次系统 Hosts，54 个项目的状态从「未读取」换成真值。现在后端只产出「未替换」「冲突」「读取失败」三档，「已生效」「部分生效」要等 Hosts 写入接上才有可比对的摘要。详情页加了这次读取的时间、第几次读取，冲突和读取失败会显示具体原因。本工具仍然不写 Hosts，测试只用临时文件，没碰系统 Hosts。 渲染这一半也已落（2026-10-29，未接线）：`Render` 按冻结的写入契约算出待写的 Hosts 全文——区段外逐行原样保留、无标记只追加、判读不了就整体拒绝、记录规范化去重后稳定排序；本包仍不写盘，也没有任何地方调用它。 备份与事务这一半也已落（2026-10-29，未接线）：`backup.go` 定了 `backups/hosts/` 里那唯一一份恢复元数据的形状（首次写入前的原始快照＋最后一次成功写入的区段摘要＋每个活动项目的应用前映射/所有权），摘要比的是规范化后的映射集合而不是字节，所以行序变了、同一个 IP 换一种写法、行内主机名重复都不算用户改了东西；`Check` 给「干净／对得上／对不上」三档，对不上时那句原因能直接显示，「有工具标记但没有记录」「说有记录但区段没了」都算对不上。`transaction.go` 给了 `Apply`/`RestoreItem`/`RestoreAll`：项目的应用前快照按主机名累计，并且只在这条映射当时没有别的项目认领时才记下当时的 IP，所以不管谁先还原，全部还原都回到原始 Hosts，也不留没人认领的残留；同一主机名被别的项目指向另一个地址时当场拒绝并说明是谁还认着它，现场一个字不动；同地址就并进去，两个项目都记成认领者。认领者集合为空是一种合法状态（工具写的旧映射暂时没活动项目认领，单项还原删不掉，等下一次应用接手）。元数据多了一条对账门：每条映射的每个认领项目，必须在自己的应用前快照里记着这个主机名。新增 27 项用例（本包顶层从 23 涨到 50，含子用例 131 条），改坏 `backup.go`/`transaction.go`/`renderer.go` 共 21 次逐条验过各自见红、还原后三个文件 `sha256sum` 与动手前逐字节一致；其中两次是有价值的失败——版本门和摘要长度门原先被更外层的门遮住、改坏了用例还绿，各补了一条能单独见红的断言，第三次暴露出元数据校验里一处永远走不到的防御代码，删掉后用对账门证明两个分支多余并一并删除。`gofmt`／`go vet ./...`／`go test -count=1 ./...` 全绿，本包 `-race`、`-count=2` 绿。这一段全是内存字符串运算，没写盘、没碰系统 Hosts、没有提权动作；`Apply` 等三个函数目前 `main.go`/`internal/app` 零引用，接线时还要翻转「拿不到可比对摘要就判冲突」那档兜底，`applied`/`partial` 才有产出条件。契约要的「逐项失败清单」也不在这层——本层的 `RestoreAll` 是全有或全无，保证不会只还原一半。
- **加速方法注册表**：`internal/accelerator/strategies/` 落地方法自注册契约与注册表——描述符声明稳定 ID、适用范围、用户文案、能力和实现，注册时逐条拦坏描述符（ID 不合法、文案为空、没声明范围、能力位缺失或未知、没有实现），同一 ID 重复注册保留先到的那份并报错，绝不静默覆盖用户配置指向的方法；查询结果按 ID 排序且是副本。第一个方法 `dns-hosts`「自动查找可用 IP」用系统配置的 DNS 取候选地址，查询不发给任何第三方解析器，一次解析最多 2 秒，候选去重、IPv4 排在前面、IPv6 去掉 zone、按上限裁断并标明是否被裁。失败分七类（超时、取消、域名不存在、零记录、解析器出错、非法域名、其他），对外只给分类加一句说明，说明里不会出现被查的域名。本步只出候选，不写 Hosts、不改系统状态；模拟解析器测试 14 项（另含 15 个子用例）覆盖超时、取消、IPv4/IPv6、各类错误和不泄漏查询域名，全程不打真实网络；注册表另有 9 项（含 13 个子用例）。注册表已在 2026-10-29 接进应用装配层（`internal/app/app.go` 固定导入该包，`newSettingsStore` 的第三个参数从硬传 `nil` 换成 `strategies.IDs()`），所以「为某个范围选默认方法」不再一律被拒：已注册的方法存得进、重开读得到，仍被拒的只有目录里没有的范围和注册表里没有的方法。`Errors()`/`UnknownScopes()` 目前由 `internal/app/registry_assembly_test.go` 两道形状门在测试期取，运行时还没有能把注册错误显示到界面的落点。
- **任务队列引擎**：`internal/task/` 落地内存任务队列——按入队顺序串行执行，同一时刻只有一条任务在跑；状态九档、终态六档和前端原型逐一对应（等待/执行中/完成/失败/跳过/已回滚/已取消/恢复中/已恢复，终态是完成、跳过、失败、已回滚、已取消、已恢复）。取消、暂停与继续、失败重试、清理已结束与清空队列全部实现并测透：暂停不打断运行中的任务，取消以取消那一刻定稿（执行器迟到的失败或进度不再改写，等待中被取消的任务耗时留空、界面显示「—」而不是假数字），重试只接受失败或已回滚的应用任务并新建记录用 `retryOf` 指回原任务、原终态不回退、批量请求逐项给新 ID 或拒绝原因，同项目已有在途任务时重复排队被挡（连点两次「检测」不会出现两条），清空队列在有任务执行中时明确拒绝，进度事件序号与快照水位用同一个计数器（1..N 连续，水位等于最后一条事件）。执行动作是注入的假件，全程不打网络、不碰 Hosts、不读系统状态；队列测试 17 项（其中结果映射含 11 个子用例），事件契约测试 3 项，全部带 `-race` 跑过，并反向验过三次（故意去掉重复排队拦截、允许取消后被改写、清空不再拒绝运行中，各自变红后原样还原）。事件名 `task:progress` 只在 `internal/event/task.go` 写一次，事件内容和快照里的任务是同一份 DTO，不抄副本。队列还没接进绑定层：`GetTasks`、`PauseQueue`、`ResumeQueue`、`CancelTask`、`RetryFailedTasks`、`ClearFinishedTasks`、`ClearQueue` 这 7 个命令仍只是契约，检测/应用/恢复三个执行器也还没实现，界面上现在排不进任何任务。

- **单实例与图标关联**：`main.go` 启用 Wails 单实例锁（UniqueID `io.github.xiaokentrl.githubnet`），二次启动由已有实例还原、显示并聚焦主窗口；macOS 使用普通应用激活策略并监听 Dock 重开事件。Linux 让 GTK `ApplicationID`、Wayland `app_id`、`.desktop` 文件名和 `StartupWMClass` 都使用产品 ID `io.github.xiaokentrl.githubnet`，桌面显示名与图标仍叫 `github-net`，不覆盖 Wails 默认的 `ProgramName`。升级后旧固定图标不会自动迁移，仍显示旧入口时需取消固定并从应用列表重新固定新的 `github-net`。此前仅对齐 `github-net` 窗口类和启动项仍未解决用户报告的程序坞重复图标，本次统一桌面应用身份，尚待目标程序坞确认运行标记和唤回行为。无会话总线时的启动失败提示已处理（2026-10-29）：`main.go` 把界面启动失败统一说成「界面没能启动：＜底层原话＞」，Linux 且确认 `DBUS_SESSION_BUS_ADDRESS` 为空时追加一句说明「这个会话没有 DBus 会话总线，单实例锁拿不到它」并给出两条出路（从桌面环境里启动，或先在终端设好该变量）；底层原话一定带出，不猜其它原因。提示只落到 stderr——这一层拿不到图形对话框。`main_test.go` 是根包第一份测试，钉住这三条。
- **删除未引用的前端资源**：`frontend/public/` 下五个文件全删——`Inter-Medium.ttf`、`bg-desktop.jpg`、`bg-mobile.jpg`、`react.svg`、`wails.png`。逐个在全库检索（排除 `node_modules`/`dist`/`.git`/打包产物，也含唯一正式原型 HTML）引用计数为 0，是 Wails 脚手架残留。之所以不是「放着也不占地方」：Vite 把 `public/` 整份抄进 `frontend/dist`，而 `main.go` 用 `embed all:frontend/dist`，所以这 702,045 B 一直在跟着二进制发货。删完 `frontend/public` 目录随之消失，`npm run build` 通过、`dist` 只剩 `assets` + `index.html`，生产参数编译产物从 11,170,848 B 降到 10,622,112 B。同目录的 `frontend/Inter Font License.txt` 是这门字体的许可文本，资源删了它成了孤儿，但它不在点名的五个里，本轮没动，等一句。
- **Actions 运行记录不再只留 1 条**：`.github/workflows/cleanup-actions.yml` 的 `keep` 从 1 调到 10。那个动作不带过滤条件时删的是**整个仓库所有工作流**的运行记录，`keep: 1` 会把门禁作业的正文和日志一起抹掉，之后想复核「当时 CI 到底绿不绿」只能重推一次；留最近 10 条既不会让页面堆成几百条，又保住证据窗口。两个触发（每周日零点 + 手动）不变。`keep≥1` 才是语义明确的用法，`keep: 0` 属未定义行为，不用。
