> 版本标签用 `v主版本.次版本.修订号`（如 `v0.1.0`），预览版带后缀（如 `v0.2.0-beta.1`）。出正式版时把「未发布」段的内容整理成该版本小节。对外首发的版本号按拍板回退到 `0.1.0`（2026-11-01）：开发期的内部号 `0.1.1`／`0.1.2` 只在本地打过标签、既没推到远端也没有 GitHub Release，所以第一个对外发布用 `0.1.0`；下面那条 `## [0.1.1] - 2026-10-31` 是开发期的定版记录，原样保留、不改名也不合并。两边分类不完全一样，是有意这么定的：仓库日志继续按 新增/修改/修复/删除 四类记；Release 正文按固定三组出——新增、修复、更新，其中「修改」和「删除」都并进「更新」这一组（条目动词写清，例如「删除了…」），没有内容的组只写一个「无」（英文段写 `None`），有条目按 `1.`、`2.`、`3.` 编号；版本类型不单独成行，并进标题（如「0.1.0 稳定版」）；中英各一份，形状由 `scripts/gen-release-notes.sh` 保证，条目内容要精简、准确、只写本版净变化。

## [未发布]

- **点「应用队列」不再写没验通的地址：过期结论先现场复验，验通才写（2026-11-06）**：用户规则原话「点击应用队列的时候，永远不要写入不能正常加速的ip」，档位拍板 C 档「新的不重测，旧的必须重测」，粒度拍板「选1，只要有任意一个通的就写已写，否则就是未写，不做过多解释」，回写拍板「都回写」。**干什么**：应用直接拿「最近一轮检测说它 available」那几条地址写系统 Hosts，而那轮检测可能是三天前跑的——候选池的保留期是 3 天，所以旧结论照样能领着一行写进 `/etc/hosts`。**为什么会错**：一次 TCP 连上＋证书验通，不代表这一会儿还通；网络变了、地址被换掉了，界面却会指着那行说「已写入」，用户以为加速生效了，实际那个地址正在把域名带到连不通的地方去。**怎么改的**：① 判据只留一条——`internal/accelerator/detect.go` 的 `Verdict`（连上并且证书对这个域名有效）导出给应用侧用，复验走的就是检测那一条判据；入口里原来那套自己数「哪条能用」的 `usableMappingsFor`／`bestPick` 和执行器里的第二套选址标准 `bestMappings` 一起删掉，选址收敛成 `Service.usablePicksFor` 一处。② 每条挑中的候选都带一个新鲜标记：内存那一轮看这轮的定格时间、候选池那一行看它的测量时间，距今超过 `applyFreshWindow = 10 * time.Minute` 就是「不新鲜」，时间字符串读不懂也一律当不新鲜（猜不出多旧就当旧的，宁可重测）。③ 执行器（`internal/app/executors.go` 的 `apply`）先报阶段「正在复验候选地址」，把不新鲜的那几条现场重探一遍——复用检测那道全进程 8 路网络闸（`Service.netGate`），不额外抬高并发；`detector.ProbeHTTPS` 是默认接缝，测试里换成 `Service.applyProbe`。④ **验通的才交给特权服务写盘**，域名粒度放行：勾中的项目里只要有一条验通就只写那几条，其余域名这一轮不写；一条都没验通就一个字不写，任务以 `failed` 落进队列，队列行上一句「候选地址现在都连不通，先重新检测再应用」——界面那一格仍是「已写／未写」两档，没有多余的第三句解释。⑤ 复验结论两处都回写：内存那一轮（`detectResultStore.markProbe`，改候选行的状态/延迟/原因并把定格时间刷成现在）与候选池那一行（`store.MarkPoolProbe`，只刷状态、延迟、测量时间三列，行本来不存在就什么都不动），所以下一轮检测和下一次应用都看得见这次现场探到的真话。⑥ 点按钮本身仍然不联网：入口的 `applyBlocker` 0）、过期结论只探被选中的那颗（未选中的调用数 0）、全失败时不写任何东西且 `ErrorMsg` 逐字相等、复验结论刷回候选池那一行（内存没记录时选址来自池）、只写验通的那个域名（另一个域名的失败不影响这条任务成功）、新鲜窗口两侧（−9m59s 算新／−10m1s 算旧／零值算旧）、候选池那一行的新鲜度、时间字符串读不懂时判为不新鲜。既有 `apply_items_test.go`
