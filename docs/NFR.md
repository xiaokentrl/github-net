# 性能与资源基线（NFR 表）

对照《性能与资源基线技术方案》一档交付物。目标环境：Linux 单平台，目标最低配 4 核 / 4GB / SSD。
复测时机：每个里程碑（发版前）；超标先归因再继续。

## 一页 NFR 表

| 指标 | 目标值 | 测量方法 | 复测时机 |
|---|---|---|---|
| 冷启动到首帧可交互 | ≤ 2.5s | 清缓存，桌面图标点击到首个可点击元素，N=10 取中位 | 发版前 |
| 空闲内存（应用进程组＋WebKit） | ≤ 250MB；静置 30min 增长 ≤ 10MB | /proc 对进程组求和 RSS，启动静置 30 分钟 | 发版前 |
| 全量检测负载内存峰值 | ≤ 空闲 +80MB（52 项完整档） | 一轮全量检测期间每 5s 采样 RSS | 大改后 |
| detect:progress 事件频率 | ≤ 50 条/秒（合并后），实测值记入本表 | 一轮全量检测在 emit 处计数 | 涉及检测链路的改动后 |
| GetItems 大 payload | ≤ 200KB / ≤ 50ms | 52 项＋池满（500 轮底账）时实测 | 目录或池结构变化后 |

## 启动路径分解（首帧前的工作）

| 步骤 | 必须性 | 说明 |
|---|---|---|
| 内嵌目录加载、配置打开、SQLite 打开 | 必须 | 同步小 IO |
| 清缓存、更新检查、自动化链 | 可延迟 | 全部等 windowReady 之后（main.go 已实现） |
| 源下载、探测 | 可惰性 | 用户触发或自动检测档位决定 |

## 内存来源清单与上限

| 来源 | 上限 | 责任清理 |
|---|---|---|
| 源内存缓存 | 30min TTL＋单源 2MiB | Fetcher loadShare |
| 源落盘缓存 | 每源一天＋3 天 prune | sources-cache |
| 检测底账（SQLite） | 3 天 prune＋500 轮兜底 | store |
| 轮预算账本（内存） | 500 轮上限（超限剪最老） | roundBudgets.pruneOldestLocked |
| 任务队列终态记录 | 200 条上限（超限剪最老，活任务不动） | queue.pruneExcessTerminalLocked |
| app.log | 1MB×2 轮转 | rotatingWriter |
| 浏览器重启去抖 | 30s 窗口（真重启成功才占） | browser_restart |
| 升级包落盘 | 3 天 prune＋只留当前下载 | cleanup/update |

## 事件频率预算

| 事件 | 预算 | 现状 |
|---|---|---|
| app:runtime-status | 恒定 0.5Hz | 符合 |
| task:progress | 每任务数条 | 符合 |
| detect:progress | 目标 ≤50 条/秒（合并后）；**已节流（2026-11-13）**：`DetectEmitter` 同候选后到覆盖＋50ms 批量投递＋单批上限 50——同候选重复转换被合并、突发洪峰被单批上限约束、持续速率由探测并发闸（8）收口；**真实全量档实测数字待录** | 候选级直发，全量档可瞬时百条级 |
