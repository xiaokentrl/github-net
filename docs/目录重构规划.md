# 目录重构规划（已拍板，待实施）

拍板 2026-11-15。程序集中 /opt/github-net/（半平铺＋libexec），配置维持 ~/.config/github-net/（XDG 标准位，零迁移），Windows 三形态规范立档、实施挂起（触发＝Windows 立项）。

## 一、Linux 终态布局

```
/opt/github-net/                    root:root 0755
├── bin/github-net                  0755  主程序
├── libexec/
│   ├── github-net-helper           0755  特权辅助服务（systemd 拉起）
│   └── github-net-root-install     0755  免密重装助手
└── share/
    ├── io.github.xiaokentrl.githubnet.desktop  0644  本体（AppID 名，identity.DesktopFile 单源；用户级软链由首启自建）
    └── icons/github-net.png        0644  图标（.desktop 里 Icon= 绝对路径）

/var/opt/github-net/                root:root 0700（FHS：/opt 包的可变数据归 /var/opt）
├── recovery.json                   0600
├── backups/hosts-original.bak      0600
└── write.lock                      0600

/usr/lib/systemd/system/github-net-helper.service  0644  deb 装，不打包 wants 链
/etc/sudoers.d/github-net-reinstall                0440  只指向 libexec/github-net-root-install
/run/github-net/                                   systemd RuntimeDirectory 托管
└── helper.sock                                    helper 内 chmod 0666（0666+SO_PEERCRED 权限模型）

~/.local/share/applications/github-net.desktop → /opt 软链（首启自建）
~/.config/github-net/               维持现状零迁移
```

### unit 定稿（用户 2026-11-15 定稿 v2，含安全沙箱）

```ini
# /usr/lib/systemd/system/github-net-helper.service
[Unit]
Description=GitHub Net privileged helper
After=local-fs.target

[Service]
ExecStart=/opt/github-net/libexec/github-net-helper
User=root
Group=root
RuntimeDirectory=github-net
RuntimeDirectoryMode=0750
Restart=on-failure
RestartSec=2
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
ReadWritePaths=/var/opt/github-net /etc/hosts

[Install]
WantedBy=multi-user.target
```

> 修正：ReadWritePaths 必须含 /etc/hosts——ProtectSystem=strict 把全盘只读化，
> 只写 /var/opt 会把 helper 的正业（写 Hosts）一起锁死（定稿 v2 遗漏，2026-11-15 复核补）。

### socket 权限模型定稿：0660＋组校验（取代 0666 拍板）

helper 创建 socket：

```c
umask(007);
bind(...);
chown("/run/github-net/helper.sock", 0, gid_of_github_net);
chmod("/run/github-net/helper.sock", 0660);
```

- 目录 0750 root:github-net，主程序用户加入 github-net 组后可进出。
- accept 后 SO_PEERCRED 校验，只接受 github-net 组内 uid。**绝不 0666。**
- （可选升级：github-net-helper.socket＋sd_listen_fds，权限交给 systemd；两种都接受，0660＋组校验是底线。）
- **这消除了 2026-11-13 审计存档的残余风险**（原 0666 模型：本机任意进程都能连 socket 调白名单操作）。
- 迁移代价：postinst 建组＋usermod -aG，**组成员资格需重新登录生效**——应用对 EACCES 要给出「重新登录后生效」的明确提示（新 UI 注意项）。

### sudoers

```
%sudo ALL=(root) NOPASSWD: /opt/github-net/libexec/github-net-root-install
```

root-install 硬约束：只接受枚举子命令，拒绝任意路径/URL 参数；只从固定源取包并校验哈希/签名；不 eval、不 `sh -c "$@"`、不跟随符号链接。

### 构建与安装行为（debhelper 链）

```make
# debian/rules
%:
	dh $@

override_dh_auto_install:
	install -Dm755 bin/github-net debian/github-net/opt/github-net/bin/github-net
	install -Dm755 libexec/github-net-helper debian/github-net/opt/github-net/libexec/github-net-helper
	install -Dm755 libexec/github-net-root-install debian/github-net/opt/github-net/libexec/github-net-root-install
	install -Dm644 share/github-net.desktop debian/github-net/opt/github-net/share/github-net.desktop
	install -Dm644 share/icons/github-net.png debian/github-net/opt/github-net/share/icons/github-net.png
	install -Dm440 packaging/github-net-reinstall.sudoers debian/github-net/etc/sudoers.d/github-net-reinstall
	install -Dm644 packaging/github-net-helper.service debian/github-net/usr/lib/systemd/system/github-net-helper.service

override_dh_installsystemd:
	dh_installsystemd --name=github-net-helper
```

debian/github-net.dirs：var/opt/github-net、var/opt/github-net/backups。不打包 wants 软链，由 dh_installsystemd 生成。apt purge 删 /opt、sudoers、unit；/var/opt/github-net 运行时文件 postrm purge 里明确是否删除，文档写清。

> 实施拍板（二选一）：**A. debhelper 全链**（本节，构建管线从 nfpm 换成 dh——更标准，dh_installsystemd 白送 enable/preset；成本＝Taskfile 打包链与「nfpm 版本==应用版本」门的重做）；**B. nfpm＋postinstall 脚本**（建组＋usermod＋enable 写进 postinstall，dst 照上表——现管线改动最小）。终态目录两案完全一致，实施前定一个。

### 首启 desktop 集成

- 仅用户级，尊重 XDG_DATA_HOME。
- 已存在且正确 → 不动；存在但错误 → 不覆盖，提示。
- GITHUB_NET_NO_DESKTOP_INTEGRATION=1 可关闭。
- 软链目标、Exec=、Icon= 全部绝对路径。

### 配套机制（三处，不写清会踩坑）

1. **开机自启**：deb postinst 走 debhelper 惯例 enable（wants 链由包脚本在安装时生成，不作为文件打包）——全新安装后 helper 必须自启，否则写 Hosts 全部 helper_unavailable。
2. **用户级 .desktop 软链首启自建**：deb 装不了 ~/.local 的东西；主程序启动自检发现无软链且 /opt 本体在，就自建（用户可写目录，安全）。
3. **socket 权限分工**：RuntimeDirectory 建目录（root 0755）＋helper 内 chmod 0666——两层各管各的，单元注释写明，防止后人「修复」成 0600 弄坏权限模型。

## 二、Windows 三形态规范（实施挂起，触发＝Windows 立项）

### 形态判定链

```
exe 同目录存在 install.json{mode=portable} → 配置根 = <程序目录>\data\
否则（mode=system|user，由安装器登记）      → system: %ProgramData%(状态)+%APPDATA%(配置)
                                            user:   %LOCALAPPDATA%\github-net(合一)
```

### system 档

```
<InstallDir>\                        默认 D:\tools\github-net，安装器可自定义；无 D 盘回退 %LOCALAPPDATA%\Programs\github-net
├── bin\github-net.exe
├── libexec\github-net-helper.exe
├── share\github-net.png
├── tools\uninstall.ps1
├── uninstall.exe
└── install.json                     {mode=system, installDir}

%ProgramData%\github-net\            ACL 锁定：recovery.json / backups\ / write.lock（Hosts 是机器全局资源，状态必须机器级）
%APPDATA%\github-net\                用户配置（同 Linux ~/.config/github-net 结构）
开始菜单 Programs\GitHub Net.lnk
HKLM\...\Uninstall\github-net        卸载登记＋安装路径
服务 github-net-helper               binPath 指 <InstallDir>\libexec\helper.exe（SYSTEM）
```

### user 档

```
%LOCALAPPDATA%\Programs\github-net\  默认，可自定义；零管理员安装
└── …（同上结构）＋ install.json {mode=user}
%LOCALAPPDATA%\github-net\           配置＋状态合一（单用户语义）
HKCU\...\Uninstall\github-net
计划任务 GitHubNetHelper（per-user, highest）——注册需一次 UAC，之后免弹
```

### 便携档

```
<任意目录>\github-net\
├── install.json                     {mode=portable}
├── bin\ / libexec\ / share\
├── tools\uninstall.ps1              可选（等价删目录）
└── data\                            配置＋状态全随包；卸载＝删整个文件夹
```

### 边界声明

- **user 档多用户边界**：Hosts 是机器全局资源，user 档状态在 %LOCALAPPDATA%——多用户共用机器时请用 system 档（各装各的 user 档会状态错位）。
- **特权模型**：system＝服务（SYSTEM）；user＝计划任务 highest（注册需一次 UAC）；portable＝每次写 Hosts UAC。Windows 侧命名管道＋SID 校验的等价设计属 Windows 立项时的实施内容。
- **元数据时效**：检查与下载之间远端再发新版 → 装完自然落后一版，启动自动重查自愈（拍板接受）。

## 五、改名支持（2026-11-15 追问定稿）

结论：**支持，且新布局必须把全部路径登记为派生值**——名字只允许在 identity.go 出现四处字面量
（DisplayName、AppID、Slug、HostsMarkerID），其余一切由它们算出，金标准门强制全链同步。

### 改名要动的（一次性，全部被门钉住）

- `identity.go`：改四处字面量；新布局引入的派生路径**必须登记成 identity 条目**，不许手写：
  `/opt/<Slug>/bin|libexec|share`、`/var/opt/<Slug>`、`/run/<Slug>`、systemd 单元名 `<Slug>-helper.service`、
  sudoers 文件名 `<Slug>-reinstall`、**socket 组名 `<Slug>`**（0660 模型新增，之前没有这条条目）。
- Windows 侧：`%APPDATA%/<Slug>`、`%ProgramData%/<Slug>`、注册表键名、服务名、计划任务名、开始菜单名——同一条派生链。
- 显示名 DisplayName 独立改（改它不动 AppID/Slug——「显示名与稳定 ID 分层」既有拍板）。

### 改名的两个真迁移坑（新装零成本，**在装机器**才有）

1. **/etc/hosts 旧区段**：HostsMarkerID 变了，旧版写进 /etc/hosts 的管理区段新版本认不出来 → 还原链对旧装机器断裂。
   迁移：新版本首启检测「旧标记存在＋新标记不存在」→ 一次性改写区段标记行（内容不变，只换标记头尾）。
2. **deb 包名更换**：新包名 ≠ 旧包名，dpkg 不会原地替换 → 在装机器上升级路径断裂。
   迁移：新包声明 `Conflicts/Replaces/Breaks: 旧包名`（dpkg 升级时自动卸旧），postinst 迁移数据（/var/opt 旧名 → 新名、配置目录 DataDir 变更走既有 MigrateLegacy）。

### 现有机制已经兜住的

- 配置目录改名 → MigrateLegacy 一次性搬家（原件保留）。
- 全部调用点的同步由金标准门强制：identity_test、main_test（appID/appName 字面）、root-install PKG 行、
  identity-guard 必检键——漏改任何一处，测试直接红。
