# 绑定层契约与生成物方案：Wails3 + Go 专用方案

## 定位与硬性目标

来源：主大纲二档「绑定与生成物」整节的六项准入问题。母法方案：《前端目录结构方案》（绑定唯一入口与依赖方向）、《安全边界与权限技术方案》（暴露面与输入校验）、《输入数据验证方案》（四层校验职责）、《状态码方案》（错误码结构与 parity）、《Wails3框架版本判别与服务纪律方案》（版本锁定与 Services 生命周期）。

本方案只管**前端与 Go 之间的那道缝**：哪些方法被暴露、暴露的模型长什么样、生成物由谁写、调用怎么出错、大数据怎么过、取消怎么传。不管窗口/事件（→《窗口与多窗口技术方案》）、不管业务状态住哪（→《应用状态与持久化技术方案》）、不管任务编排（→《任务队列方案》）。

**硬性目标**：

1. 绑定目录由生成器独占，任何人不得手工编辑；CI 有 `生成 → diff` 门禁；
2. 每个暴露方法都有「只读 / 写 / 管理」标注与校验策略，**Service 的导出方法默认可被前端调用**；
3. 方法名、参数、模型字段视为对外契约，改名必须重新生成并对账，不允许「前端静默错调」；
4. 错误与取消都是结构化协议，不靠异常字符串和猜测。

不预设：框架小版本、前端框架、生成命令名、payload 上限、绑定目录路径。所有具体值由项目锁定版本后核实，未核实的标**待验证**。

## 一、暴露面：导出即公开

先查清锁定的 Wails 版本里「什么算暴露」，再逐个登记。禁止凭 v2 经验推断 v3 行为（→《Wails3框架版本判别与服务纪律方案》）。

| 项 | 要登记什么 | 验收证据 |
|---|---|---|
| 暴露清单 | 每个绑定方法：名称、所属 Service、只读/写/管理、输入校验策略、是否需鉴权 | 绑定方法清单（可由生成器/静态扫描产出，与源码同步） |
| 非暴露面 | 只给 Go 内部用的方法一律不导出；helper 不挂 Service | 扫描「导出方法数」与清单数量一致，多一个即失败 |
| 校验归属 | 边界层做规范化与结构校验，领域层做业务规则（→《输入数据验证方案》）；不得只在 UI 隐藏按钮 | 每个写/管理方法的校验函数位置 |
| 高权限 | 需要管理员权限的操作拆到独立 Core，经鉴权 IPC 通信，主进程普通权限运行 | 进程边界图 + IPC 鉴权方式（→《安全边界与权限技术方案》） |

**常见根因**：把内部 helper 写成导出方法，等于无声开放一个未校验的写接口；前端能直接执行系统命令的路径一旦存在，任何 UI 层的禁用都不构成防护。

## 二、绑定模型的类型禁区

绑定模型是**跨语言的数据容器**，不是领域对象。逐项确认类型在锁定版本的支持范围内；查不到源码依据的一律标待验证，不照抄其他框架清单。

| 判定 | 允许 | 禁止／需实证 |
|---|---|---|
| 字段 | 基本类型、由基本类型组成的 struct、slice/map of allowed types、明确的指针/可选语义 | channel、func、复杂 interface、未导出字段、循环引用、带方法的对象、依赖运行时状态的字段 |
| 时间 | 统一口径（UTC 时间戳或带时区的字符串），Go/TS 双侧同一解析规则 | 本地时间字符串、格式化后的展示值（→《格式化与货币本地化方案》） |
| 枚举 | 数值或字符串枚举 + 前向兼容未知值分支 | 用零值兼职「未设置」哨兵（→《状态码方案》《窗口与多窗口技术方案》） |
| 命名 | 字段名、方法名进契约表，改名走 breaking change 流程 | 顺手重命名、复用旧名字表达新语义 |

**模型清单**要能回答：新增字段旧客户端能否忽略？删除字段旧数据能否读入？字段类型收紧后落盘的历史值怎么办？答不上来就先别改。

## 三、生成物单一源与对账

四条纪律：

1. **生成器独占**：绑定目录（含 TS 模型与索引）整目录由生成器重写，目录头注明「请勿手工编辑」；手工补一个类型 = 下次生成被抹掉，或更糟——留下一份与源码不同的假契约。
2. **单一生成命令**：生成步骤写进 `Taskfile`/`Makefile`/脚本的**一个**入口，本地、CI、打包前都调它；不允许三条路径各拼一段参数。
3. **同步门禁**：CI 执行 `生成 → git diff --exit-code`，有差异即失败；同时检查生成物与源码的模型哈希/方法 ID 对账（若框架提供哈希 ID，必须纳入，不能只看文件是否变化）。
4. **前端唯一入口**：组件不得直接 import 生成目录，一律经自定义 hook/绑定封装层（→《前端目录结构方案》）；封装层集中处理加载态、错误码映射与取消（→《长任务与后台工作技术方案》）。

**改名场景的正确顺序**：改 Go 签名 → 重新生成 → 更新封装层与调用点 → parity 门 → 提交。只改 Go 侧或只改前端，都会得到「编译通过但调用到另一个方法」的静默错调。

## 四、错误契约与 parity

- 后端返回**结构化错误**：错误码 + 受影响字段 + 是否可重试 + 关联 ID；码值结构与登记表以《状态码方案》为准，成功不设码，panic 不进码表。
- 中间层只 wrap（`%w` 加上下文）不重新分配码；批量失败聚合并逐子错误映射（→《Go测试与文件系统模式方案》）。
- Go 侧码表与 TS 侧映射表**由同一份定义生成**，CI 跑 parity 测试：少一个映射、多一个未知码、码义变更，全部失败。
- 前端展示文案与错误码解耦：码决定「发生了什么」，文案决定「怎么告诉用户」（→《操作反馈方案》《弹窗按钮文案方案》）。

## 五、大 payload 与取消语义

| 场景 | 判定 | 做法 |
|---|---|---|
| 返回值／事件载荷 | 先设上限并实测；框架或 WebView 的 body 限制按锁定版本核实（**待验证**：常见 WebView2 路径有 2MB 量级限制） | 超过上限改分页／分块／流式；禁止「先返回全量再让前端截取」 |
| 流式接口 | 区分字节语义与字符串语义 | 按字节处理，明确编码边界与结束条件；不要按字符数切 |
| 高频事件 | 分发频率与 payload 大小纳入 NFR（→《性能与资源基线技术方案》《UI数据一致性实现方案》） | 信号只发失效不发数据，节流/合并 |
| 长任务取消 | custom scheme 下客户端中止**不一定**传播到 Go 侧 `r.Context()`（真实 HTTP / dev server 路径才会）→ 标待验证并实测 | 长任务改走绑定调用：Go 签名首参 `ctx`，循环内设检查点，前端保存可取消 Promise 并提供取消入口（→《长任务与后台工作技术方案》） |

**不要假设「调用没报错＝生效」**：框架在窗口实现未创建时对某些调用是空操作（→《托盘技术方案》的时序契约纪律）。绑定调用的取消与初始化时序要一起验。

## 六、常见根因表

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 方法改名后前端偶尔调到旧逻辑 | 生成物未重新生成／哈希 ID 未对账，或走了另一套生成参数 | 单一生成命令 + `generate → diff` 门 + 唯一入口 import |
| 生成物被覆盖、手工补的类型消失 | 有人手改了生成器独占目录 | 目录头警告 + CI 检查生成物与源码一致 |
| 大列表偶发空白或截断 | 返回值超过 WebView body 限制，或流式按字符切字节 | 上限判定表 + 分块/分页 + 字节语义测试 |
| 取消后后台还在跑 | 依赖 custom scheme 的 `r.Context()`，实际未传播 | `ctx` 贯穿绑定调用 + 循环检查点 + 取消入口 |
| 错误提示前后端不一致 | 两处各写一份码表，没有 parity 门 | 码表单源生成 + CI parity 测试 |
| 前端能触发不该有的高权限动作 | Service 导出方法默认暴露，内部 helper 写成导出 | 暴露面清单 + 导出方法数静态门 + 高权限隔离 |

## 七、验收清单

1. 绑定方法清单：逐项「只读/写/管理 + 校验策略」，与导出方法数一致；
2. 绑定模型清单：字段类型在支持范围内，时间口径、枚举未知值、零值哨兵逐项确认；
3. 生成物对账：单一生成命令、`git diff --exit-code` 门、模型/方法 ID 一致性证明；
4. 错误契约：结构化错误示例 + Go/TS parity 测试通过记录；
5. payload：上限实测记录、超限路径的分块/分页证据、流式字节边界用例；
6. 取消：长任务清单 + `ctx` 贯穿路径 + custom scheme 与真实 HTTP 两条路径的实测结论（含「待验证」项）；
7. 三平台冒烟：Windows / macOS / Ubuntu 26.04 下生成、绑定调用、大返回值、取消各跑一遍，未跑的标未验。

## 给 AI 的实施约束模板

> 先盘点仓库里所有绑定 Service 的导出方法、生成命令、生成目录、前端 import 绑定目录的位置，以及锁定的 Wails 版本源码里绑定类型与暴露规则。给出暴露面清单（只读/写/管理 + 校验策略）、绑定模型清单、单一生成入口与 `generate → diff` 门禁、Go/TS 错误码 parity 测试、payload 上限与取消链路设计。**生成物目录禁止手工编辑；方法名与模型字段名视为对外契约，改名必须重新生成并对账；组件不得直接 import 生成目录；长任务不得依赖 custom scheme 的 `r.Context()` 作为唯一取消来源。** 任何行为以当前项目锁定的框架版本源码为准，查不到证据的写「待验证」，不得照抄其他版本结论。实现后给出可观察的回归测试（生成物不一致即失败、码表少映射即失败、取消后 goroutine 退出、超限 payload 被分块），并列出未实测平台。所有名称、路径、上限由当前项目需求决定。

| 档位 | 本方案承担 |

| 一档 | 暴露面清单与校验策略、前端唯一入口纪律（不回答不写业务代码） |
