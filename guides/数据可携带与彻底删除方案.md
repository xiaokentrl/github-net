# 数据可携带与彻底删除方案：通用规划方案

## 这份方案是做什么的

来源：GDPR 合规清单的「数据主体权利落实」「数据保留与删除策略实施」「在数据模型中设计删除机制」三项、本地优先应用的用户数据所有权实践、主大纲四档「发布说明与变更记录」之外的数据生命周期条目。

母法方案：《数据模型与数据契约方案》（ID、schema 版本、软删除与 tombstone）、《应用状态与持久化技术方案》（落盘、备份、迁移）、《默认安装目录规划方案》（卸载净空）、《磁盘资源缓存管理方案》（缓存与副本）、《遥测与隐私合规方案》（DSAR、留存、子处理者）、《本地敏感数据与密钥管理方案》（凭据删除）、《输入数据验证方案》（导入是外部输入）。

它管**「用户能不能把自己的数据完整带走，以及说删之后到底删没删干净」**：导出格式与回环、导入幂等、删除范围（含副本）、卸载行为、审计留痕。《默认安装目录规划方案》管程序文件卸载净空，本方案管**用户数据**的可携带与删除，两者互补。

不预设：导出格式、是否云同步、保留期限、法规适用。所有具体值由产品与法务决定。

## 开始写代码前，先让 AI 回答这些问题

1. 用户数据分布在哪：主库、附件/文件、缓存、日志、备份、导出历史、崩溃诊断、支持附件、云端副本（若有）？**有没有一张按存储位置的清单**？
2. 导出包含什么、不包含什么（凭据、token、日志、缓存是否排除）？格式版本与 schema 版本如何标记？
3. 导出是否可回环导入：导入后 ID、关系、时间口径、附件是否完整？重复导入是否幂等（→《数据模型与数据契约方案》）？
4. 导入是外部输入：规范化、消毒、路径前缀校验、大小/数量上限在哪（→《输入数据验证方案》《外部链接与协议回调安全方案》）？
5. 导出文件如何保护：是否加密、权限 `0600`、是否含敏感字段、用户能否选择性导出（→《本地敏感数据与密钥管理方案》）？
6. 「删除」有几种语义：删单条、清空全部、注销账号、卸载应用、撤回同意？每种各自删除范围与保留例外是什么？
7. 软删除 + tombstone 的恢复窗口与同步/备份重放如何避免「删了又回来」（→《多端数据同步方案》）？
8. 删除请求要覆盖哪些副本：主库、缓存、日志、备份快照、临时导出、支持附件、崩溃记录、云端副本？每个副本的 owner 与删除任务是什么？
9. 保留例外（法律、安全、计费、审计）如何标记、到期如何自动解除（→《遥测与隐私合规方案》）？
10. 卸载时：哪些用户数据保留、哪些删除、用户如何先导出？托管策略残留与凭据怎么处理（→《默认安装目录规划方案》《企业部署与托管配置方案》）？
11. 删除是否留审计记录？记录里是否含被删内容（→《日志与可诊断性技术方案》）？
12. 删除失败/部分失败如何呈现给用户？能否重试、能否出具「删了什么、保留了什么、为什么」的结果说明？
13. 是否有真实演练：发起一次删除请求，逐系统检索并计时，验证副本确实清除（→《遥测与隐私合规方案》的 DSAR 工作流）？

交付给 AI 的设计结果应包含：数据位置清单、导出契约与回环、导入校验、删除语义矩阵、副本删除 owner 表、保留例外、卸载行为、审计与演练记录。

## 核心纪律

### 一、数据位置清单：删不干净几乎都是「漏了某个副本」

| 位置 | 例子 | 删除 owner | 自动任务 |
|---|---|---|---|
| 主库 | 实体、关系、软删除标记 | 领域服务 | 到期清理 |
| 附件/用户文件 | 导入的文档、图片 | 文件服务 | 引用计数归零后删 |
| 缓存 | 缩略图、临时渲染 | 缓存服务 | 容量/到期（→《磁盘资源缓存管理方案》） |
| 日志/诊断 | 结构化日志、崩溃文件、诊断包 | 日志服务 | 留存到期（→《日志与可诊断性技术方案》） |
| 备份/快照 | 预迁移备份、滚动备份 | 持久化服务 | 过期策略（→《应用状态与持久化技术方案》） |
| 导出历史 | 用户手动导出的文件、临时工程导出 | 导出服务 | 到期 + 用户可见入口 |
| 支持/云端 | 工单附件、崩溃监控记录、云端副本 | 支持/服务端 | DSAR 流程（→《遥测与隐私合规方案》） |

**「只删生产库」是最常见的假删除**；备份与导出副本往往留存更久，且没人记得它们在共享盘里。

### 二、导出/导入契约

| 项 | 要求 |
|---|---|
| 格式 | 显式 `formatVersion` + `schemaVersion` + 校验和；未知版本明确拒绝或走迁移 |
| 内容 | 用户数据 + 必要元数据；排除凭据、token、缓存、日志；敏感字段按决策加密 |
| 口径 | UTC 时间、规范化数值、稳定 ID，不存格式化展示值（→《数据模型与数据契约方案》《格式化与货币本地化方案》） |
| 幂等 | 稳定 ID + tombstone，重复导入不产生重复实体（→《原子性提交方案》） |
| 校验 | 导入走四层校验与路径前缀/`os.Root` 类约束；不反序列化任意类型（→《输入数据验证方案》《Go测试与文件系统模式方案》） |
| 失败 | 保留原数据，明确报告哪一条失败；禁止「导入失败但库已半改」 |
| 权限 | 导出文件 `0600`，写入原子提交，失败留可诊断记录（→《原子性提交方案》） |

**可携带性的验收是回环**：导出 → 在干净环境导入 → 逐实体比对，而不是「文件生成成功了」。

### 三、删除语义矩阵

| 语义 | 范围 | 保留例外 | 用户结果说明 |
|---|---|---|---|
| 删单条 | 实体 + 引用 + 缓存 + tombstone | 审计计数（不含内容） | 已删除、可恢复窗口 |
| 清空全部 | 主库 + 附件 + 缓存 + 导出历史 | 日志按留存 | 明确清单 |
| 撤回同意 | 已上传可识别遥测/诊断 | 聚合匿名指标（写明理由） | 删了什么、留了什么 |
| 注销账号 | 账户 + 云端副本 + 支持记录 | 法律/计费 | 逐系统结果 |
| 卸载应用 | 程序文件、服务、协议注册 | 用户数据（按产品决策）或一并删除 | 先导出入口（→《默认安装目录规划方案》） |

- 软删除必须有 tombstone 与恢复窗口，防止旧设备/备份重放把数据复活（→《多端数据同步方案》）。
- 保留例外必须带**到期日与自动解除任务**，不能变成永久保留的借口。
- 删除是事务性的：跨资源按《原子性提交方案》的三模式设计，部分失败要能重试且不留半成品。
- 审计记录只留「什么类型、何时、由谁触发、结果」，不留被删内容。

### 四、演练与证据

- 用真实场景跑一次：发起删除 → 按系统映射图固定顺序检索 → 逐副本清除 → 出具结果说明 → 计时。若需工程师手工查表几小时，流程不成熟（→《遥测与隐私合规方案》）。
- 自动化就是策略：到期任务、生命周期规则、例外工单标记；靠人记得删一定会漏。
- 硬件/介质与备份快照按各自过期策略处理；介质销毁流程可审查。
- 无论许可状态或账号状态如何，导出数据都应可用（→《授权与许可方案》）。

## 常见根因表

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 删掉的数据又出现 | 无 tombstone，旧备份/旧设备重放 | 软删除 + tombstone + 幂等重放 |
| 删除请求只删主库 | 副本无 owner 与到期任务 | 按位置清单 + 自动清理 |
| 导入后重复记录 | 导入不幂等、无稳定 ID | 稳定 ID + 去重（→《数据模型与数据契约方案》） |
| 导出文件打不开/版本不认 | 无 formatVersion/schemaVersion | 版本标记 + 明确拒绝/迁移 |
| 导出带出凭据或日志 | 全量打包未设排除清单 | 内容白名单 + 权限收紧 |
| 「保留例外」永久不删 | 例外无到期与自动解除 | 有效期 + 到期任务 |
| 卸载后用户数据没了/没删干净 | 卸载行为未与产品决策对齐 | 卸载语义矩阵 + 先导出入口 |
| 部分失败留下半成品 | 跨资源删除无事务边界 | 事务三模式 + 重试（→《原子性提交方案》） |

## 先设计测试矩阵，再开始实现

| 维度 | 要覆盖 |
|---|---|
| 回环 | 导出→干净环境导入→逐实体/附件/时间口径比对；重复导入幂等 |
| 导入 | 未知版本、损坏文件、路径逃逸、超大数量、任意类型反序列化 |
| 删除 | 单条/清空/撤回/注销/卸载逐语义；主库与每类副本断言已清 |
| 复活 | 旧备份重放、旧设备同步、崩溃后重启 |
| 例外 | 保留项有理由与到期自动解除 |
| 失败 | 磁盘满、部分副本不可达、重试后最终一致 |
| 演练 | 真实 DSAR 场景计时并出具结果说明 |

## 给 AI 的实施约束模板

> 先给出按存储位置的数据清单（含每类副本 owner 与到期任务）、导出/导入契约（formatVersion/schemaVersion/校验和/排除清单/幂等键）、删除语义矩阵、保留例外与到期、卸载行为、审计与演练记录，再写导出删除代码。**可携带性以导出→干净环境导入的回环比对验收；导出排除凭据/token/缓存/日志且文件权限收紧；导入是外部输入，走规范化、消毒、路径前缀校验且不反序列化任意类型；软删除必须配 tombstone 防复活；删除覆盖所有副本，仅删主库不算完成；保留例外必须有到期自动解除；跨资源删除按事务边界设计、部分失败可重试；无论许可或账号状态如何都要能导出数据。** 任何「已删除」「已导出」必须附可观察证据。实现后给出回环、删除、复活、失败的可观察测试与一次真实 DSAR 计时演练，并列出未覆盖系统。所有格式、期限、例外由当前项目与法务决定。

## 五档定位

| 档位 | 本方案承担 |
|---|---|
| 一档 | 数据位置清单、导出/删除的产品决策（不回答不写落盘代码） |
| 二档 | 导出契约、导入校验、删除语义矩阵、副本 owner |
| 三档 | 保留例外、审计留痕、卸载行为与先导出入口 |
| 四档 | 到期自动化、DSAR 演练与结果说明——进入受监管市场前不得发布 |
| 五档 | 云端副本/跨设备删除可按产品形态暂缓（写理由 + 触发条件：出现账号或云端副本时重评，→《多端数据同步方案》《登录与权限方案》） |
