# 主题与色彩：通用方案

## 这份方案是做什么的

《多平台一致组件库方案》定了令牌的**机制**（单源、生成 CSS vars、禁裸值）；本方案定色彩的**内容**：调色板怎么构造、语义色怎么映射、暗色主题怎么派生、对比度怎么保证、主题有哪几档、accent 跟谁走。

**硬性目标**：界面上不存在「设计时随手挑的颜色」——全部颜色从一套受控调色板推导；明、暗、高对比三主题是**推导关系**而非各画一遍；色彩对比在 CI 里可验证。

**与相邻方案的分工**：令牌基础设施 →《多平台一致组件库方案》；主题跟随系统与深色监听 →《系统能力与平台集成技术方案》；对比度与色盲的无障碍要求 →《无障碍与辅助技术方案》；主题选择持久化与首帧前就绪 →《应用状态与持久化技术方案》。

## 色彩系统三层（组件只见语义层）

```
① 基础色阶（primitives）   gray-0…gray-100、brand-10…90、red-…、green-… 每色相受控阶数
        ↓ 映射
② 语义令牌（semantic）     bg / surface / surface-raised / border / text / text-muted /
                          primary / primary-hover / danger / warning / success / info / focus
        ↓ 消费
③ 组件样式                 只允许引用 ②，禁触 ①（裸值扫描见组件库方案）
```

- **换主题 = 换 ② 的映射，① 不动**：亮暗两套语义映射指向同一套基础色阶——这是「推导而非重画」的结构保证。
- 中性灰阶带**色温决策**：纯灰偏冷易呆，微暖/微冷灰有质感——选一个记录进调色板文档，不混用。
- 组件级别名（`button-primary-bg`）只在真实需要时加，不许把语义层淹没在别名里。

## 主题档位与 accent 决策

| 档位 | 来源 | 说明 |
|---|---|---|
| 亮 / 暗 | 跟随系统 + 手动覆盖（设置单源 → 状态方案；深色监听 → 系统能力方案） | 必备两档 |
| 高对比 | 合规声明决定（→ 无障碍方案） | 有辅助技术用户才做，做则独立令牌集 |
| accent 色 | **二选一并记录**：跟随系统 accent（平台尊重点，各平台读取能力**待验证**，不支持则固定色降级）或品牌固定色 | 不许半跟半不跟 |
| 用户自定义主题 | 仅立项需要时做；自选色限 accent 单点，不开放全套调色板 | 防主题拼贴 |

## 暗色派生纪律（最容易翻车的一段）

- **暗色不是反色、不是滤镜**：语义层独立映射——彩色在暗底上要**提亮、去饱和**（亮主题的品牌色直接搬进暗底会刺眼且发闷），品牌色明暗各校准一版。
- **层次用明度差，不用阴影**：亮主题用阴影表达海拔（elevation），暗主题阴影不可见——改用 surface 逐级提亮；两套 elevation 策略都是令牌（阴影令牌 + surface 阶），组件不关心当前在哪个主题。
- **边界在暗色下更亮而非更暗**：border 令牌在暗色映射里提亮。
- **数值底线**：避免大面积纯黑（`#000`）与纯白文字（`#FFF`）——各用近黑/近白的受控阶（如 `gray-100 / gray-5`），写进调色板文档作为纪律而非建议。
- 暗色下的 focus ring 与选中态必须单独校验可见性（→ 无障碍方案焦点可见）。

## 对比度纪律（可进 CI 的部分）

- 目标等级按合规声明定（默认 WCAG AA 量级：正文 4.5:1、大字与图形 3:1，→ 无障碍方案）。
- **语义组合矩阵自动化**：列出全部「文本令牌 × 背景令牌」的合法组合，对比度检查脚本进 CI——设计期调坏一处配色，构建期就红，不等到用户投诉。
- 状态不只靠色（错误/成功加图标文字）→ 无障碍方案第二通道；本方案保证色彩通道本身达标。
- 图表/数据可视化色板与 UI 语义色**同源但分板**：分类色板预校验色盲安全与互相区分度，上限类别数记录在案；**语义红不许挪作图表装饰色**（色彩语义漂移）。

## 色彩使用纪律

- **语义色用途固定**：`danger` 只表示破坏/错误，`success` 只表示成功——任何「顺手用红色好看」都是语义漂移，评审可拒。
- 中性为底、彩色为点：大面积界面走中性阶，品牌/状态色做强调（60-30-10 量级参考，非硬数）。
- 全部颜色的出生地是 ① 基础色阶——本方案是全库「合法颜色的唯一产地」（组件库方案裸值禁令的供给侧）。

## 切换机制

- 主题切换 = 切语义令牌集（CSS vars 根节点切换），即时、无刷新。
- **防首帧闪烁（FOUC）**：主题令牌在首帧前注入——启动时先读设置里的主题再渲染（→ 状态方案就绪分级「首帧必须」；冷启动无闪烁进验收）。
- 主题过渡动效尊重「减少动态效果」（→ 无障碍方案）。

## 交付物与验收清单

- [ ] 调色板文档：基础色阶 + 明/暗语义映射表 + 色温与数值底线决策
- [ ] accent 决策记录（跟随系统或品牌色，降级路径已写明）
- [ ] 对比度组合矩阵进 CI 且当前全绿
- [ ] 明/暗（+高对比）三主题组件卡截图成对（→ 组件库方案组件卡）
- [ ] 冷启动无主题闪烁（目标最低配机器实测）
- [ ] 图表分类色板色盲预校验记录
- [ ] 跟随系统 + 手动覆盖 + 重启保持全链路验证

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 暗色刺眼或发闷 | 亮色直接搬进暗底 | 暗色独立派生 + 品牌色双版 |
| 暗色下层次糊成一片 | 阴影不可见、无 surface 提亮策略 | elevation 双策略令牌 |
| 某组件对比度不足 | 手挑颜色绕过语义层 | 语义组合矩阵进 CI |
| 切主题/启动闪一下 | 主题在首帧后才确定 | 首帧前注入 + 冷启动验收 |
| 红色既是错误又是装饰 | 语义色挪用 | 用途固定 + 评审可拒 |
| 图表多系列分不清 | 无色盲预校验、无分类色板 | 分类色板同源分板 |
| accent 在某平台不生效 | 平台能力未核实 | 待验证 + 固定色降级 |
| 用户改主题后重启丢失 | 主题不在首帧就绪清单 | 状态方案就绪分级 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 先产出调色板文档（基础色阶、明暗语义映射、色温与数值底线）与 accent 决策记录。组件样式只引用语义令牌；明暗两套映射指向同一基础阶，暗色按派生纪律（彩色列提亮去饱和、层次用 surface 提亮、边界提亮、近黑近白）；语义色用途固定不挪用；语义组合对比度矩阵生成并进 CI；图表分类色板独立预校验；主题切换 = 切根节点令牌集，主题值首帧前注入防 FOUC；跟随系统走监听非只读一次。平台 accent 能力先核实，未核实标注待验证并带固定色降级。实现后跑验收清单（三主题截图成对、冷启动无闪烁），并明确列出未覆盖的组合。

方案确认后再改代码；调色板定稿属设计决策，AI 给方案与数据（对比度实测），最终色彩选择由用户裁决。

## 五档定位

- **一档**：基础色阶 + accent 决策 + 明暗映射草案。
- **二档**：语义组合对比度矩阵进 CI；三主题组件卡成对；FOUC 验收。
- **三 / 四档**：高对比主题、图表分类色板、跟随系统全平台验证。
