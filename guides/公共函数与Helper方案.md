# 公共代码：函数、方法与 Helper 方案

## 这份方案是做什么的

《后端目录结构方案》《前端目录结构方案》**禁止** `utils / common / misc / helper` 垃圾包——但公共代码是真实需求，禁令必须有正面出口。本方案回答：公共函数/方法/helper **按什么归类、什么时候提取、放哪里、怎么防止既不垃圾场化也不过早抽象**。

**病根一句话**：垃圾包的成因是**按「被谁用」归类**（被多方使用 = 进 utils），而「被谁用」不是分类学——什么都迟早被多方用，所以 utils 什么都装。本方案的反面规则：

> **公共代码按「它是什么能力」命名归类，不按「它被谁用」。** `clock`、`ids`、`retry`、`humanize` 是好名字；`utils`、`helper`、`common` 永远不是。

## 写少阶梯（写之前先过七级）

判定流程回答「写好的代码放哪」，本节回答「这段代码要不要写」——**先问要不要写，再问放哪**。来源：go-skills 的 Necessity Ladder（MIT，Steve Francia）。**动手前停在第一个成立的梯级，爬完**——两个梯级都可行时取高的那个：

1. **真的需要吗？**「以后会用」不是需要——跳过，并用一行说明跳过原因；
2. **库里已经有了吗？** 写前先查重——helper/类型/模式可能已在别的包（重复造轮子是本阶梯最常见的失守点，组件库演示/导出查重同规）；
3. **标准库有吗？**（Go 侧）`slices`/`maps`/`cmp` 代替手写循环、`errors.Join` 代替 multierr、`slog` 代替日志模块——这一级拦下的最多；
4. **平台/工具链有吗？** `//go:embed` 代替资产管线、`os.Root` 代替手写路径围堵、`sync.OnceValue` 代替懒加载 helper、DB 约束/唯一索引代替应用层校验；
5. **go.mod 里已有吗？** 用已付费的依赖——为几行代码新增一个模块是失守；但 errgroup、afero、go-cmp 这类值得引入的不算（已明确的推荐项）；
6. **能是一行吗？** 那就写一行；
7. **否则：最小可用实现**——无多余文件/层/旋钮；单实现的接口、单产品的工厂、永不变值的配置字段都是第 7 级失守。

**永不因写少而砍**：信任边界的校验、防数据损失的错误处理、安全、清理、显式要求的功能。

**命名天花板**：最小实现若有已知极限，把极限写在极限所在处（`// yagni: 全表锁——写吞吐上来了再分键锁`）。写明的天花板是简化，没写的是地雷。

**修根因不修上报路径**：bug 报告只点名症状——动函数前先 grep 全部调用方；一处所有调用方必经的守卫，小于每个调用点各加一道。

## 判定流程（一段代码该去哪）

```
这段代码只有本领域用？
 ├─ 是 → 领域包内私有（不导出；实现细节，死了不心疼）
 └─ 否，别处也要用？
      ├─ 这是第 2 处 → 先复制，两份各留一行注释指向对方（漂移预警）
      └─ 这是第 3 处，且签名已稳定？
           ├─ 是 → 提取为具名能力包（clock / retry / textx / …）
           └─ 第二个项目也要用？→ 提升进跨项目积累库（lib-go）
```

**三次规则是本方案的心脏**，两个方向都强制：

- **不许第 1 次使用就抽象**——过早抽象（猜的通用性）比复制更贵：错误的抽象会让三个使用方一起变形。复制是廉价的，错误的抽象是昂贵的。
- **不许第 3 处复制还不提取**——第三份拷贝出现时，提取从「可选优化」变成「义务」：漂移已经发生，两份改了一份的 bug 就在路上了。

## 落位结构

**Go 侧**（衔接《后端目录结构方案》，internal 之外无代码）：

```
internal/
├── <domain>/          # 领域私有 helper：不导出，仅供本领域
├── clock/             # 具名能力包：时间源（可注入、可测试）
├── ids/               # ID 生成
├── retry/             # 退避重试（→ 网络方案共用）
├── textx/ size/ …     # 其余按能力命名，一包一职责
跨项目积累（可选目录，与 guides/、ui/ 同哲学）：
lib-go/               # 多项目验证过的能力包，独立 module，semver，回流纪律
```

**前端侧**（衔接《前端目录结构方案》，判定流程完全相同）：

```
src/lib/              # 纯函数：format/（Intl 单点）、ids、time——无框架依赖
src/hooks/            # 框架层公共：只有真的用了 hook 才叫 useXxx；
                      #   订阅类 hook 强制成对清理（→ 同步方案监听器生命周期）
```

## 能力包准入四件套

一个能力包（`clock/`、`retry/`…）成立，必须同时有：

1. **单一职责**：包名 = 能力；godoc 首行一句话说清它是什么、不是什么；
2. **依赖只向下**：能力包不 import 领域包、不 import binding——它是最底层，被所有人用的人不反咬任何人（`retry` 可以用 `clock`，`clock` 不依赖任何兄弟包）；
3. **测试**：纯逻辑包的测试不依赖 UI、不依赖数据库；
4. **用例示例**：godoc Example 或 README 片段。

## 函数 vs 方法 vs 选项

- **无状态变换 → 纯函数**（`humanize.Bytes`）；**有状态或需多态 → 方法挂类型**；**全局可变状态 → 禁止**（可注入的 `clock.Now` 优于全局单例）。
- **布尔开关参数是反模式**：`render(true)` 读不出语义——那是两个函数挤在一个签名里，拆成 `renderCompact / renderFull`；参数持续增长用 options 结构，不用位旗标。
- **不做纯转发的中间层**：一个函数若只是转调另一个函数，删掉它——helper 层层嵌套是垃圾包的变体。
- **命名**：包名短小能力化；函数名不重复包名（`retry.Do` 而非 `retry.RetryDo`）；导出即承诺——没准备好被依赖的不导出。
- **零值可用**：类型设计成零值直接能用，不需要初始化仪式（`sync.Mutex`、`bytes.Buffer` 是金标准）——省掉样板构造器；能力包的配置结构体同样适用：零值 = 合理默认。
- **接口三条**（来源：go-skills，MIT）：
  1. **接口是发现的，不是预先设计的**——先写具体类型，等消费者真的需要多型替换时才提接口；
  2. **接口定义在消费者包**，不是实现者包——实现者不该知道接口存在（`UserFetcher` 定义在用它的 processor 包）；这也正是手写 fake 可行的前提（→《Go测试与文件系统模式方案》）；
  3. **接受接口，返回具体类型**——参数收最小接口（`io.Reader` 优于 `*os.File`），返回结构体，调用方不必类型断言就能取字段。

## 结构守门清单

- [ ] 全库无 `utils/common/misc/helper` 包（lint/编译期强制）
- [ ] 每个能力包四件套齐（职责文档、依赖向下、测试、示例）
- [ ] 三次规则有执行痕迹：提取的包在 doc 里写明三个用例来源
- [ ] 无布尔开关参数（审查）；无纯转发中间层
- [ ] 新增代码过了写少阶梯（第 2 级查重有执行痕迹；第 7 级实现带 `// yagni:` 天花板标注或无极限）
- [ ] 能力包零领域 import（grep 审查）
- [ ] 前端 `hooks/` 中订阅类 hook 全部成对清理

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| utils 膨胀成垃圾场 | 按使用方归类 | 「按能力命名」判定流程 |
| 改一处坏两处 | 该提取没提取，拷贝漂移 | 第三次复制强制提取 |
| 改通用函数三处全变形 | 过早抽象，签名是猜的 | 三次规则：第 1 处禁止抽象 |
| 能力包反向依赖领域 | 贪方便塞了个回调 | 依赖只向下 + grep 审查 |
| `render(true)` 无人读懂 | 布尔开关参数 | 拆函数 / options 结构 |
| helper 里套 helper | 纯转发层越积越多 | 转发层即删 |
| 跨项目各改各的 | fork 不回流 | 与组件库同规：回流纪律 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 新代码先过写少阶梯（需要吗→库里→标准库→平台→go.mod→一行→最小实现），再走判定流程：领域私有 → 复制预警 → 第三处提取为具名能力包。禁止创建或扩充 utils/common/misc/helper 包；能力包一包一职责、依赖只向下、带测试与示例，godoc 首行说清职责。三次规则双向强制：第 1 处使用不许抽象，第 3 处复制必须提取；复制件互留指向注释。接口是发现的不是设计的：先具体类型，消费者包里才定义接口，接受接口返回具体类型；类型零值可用。纯变换用函数、有状态用方法、禁全局可变状态；布尔开关参数拆成两个函数或 options；纯转发中间层删除。最小实现的已知极限用 `// yagni:` 写明。前端纯函数进 `lib/`、真 hook 才进 `hooks/` 且订阅类成对清理。实现后跑结构守门清单。

方案确认后再改代码；提取时机拿不准（第 2.5 处）时，先报告用例再裁决，不擅自抽象。
