# 单实例与快速启动：Wails3 + Go 专用方案

## 定位与硬性目标

母法方案：《窗口与多窗口技术方案》（二次启动参数路由）、《应用状态与持久化技术方案》（首帧前后状态分档）、《长任务与后台工作技术方案》（重活出主线程）。本方案管三件事的**纪律与预算**：单实例启动（默认）、启动时间预算、UI 响应下限。

**硬性目标**：

1. 单实例是默认：二次启动不产生第二个进程——参数/文件/URL 路由到已有实例的对应窗口；
2. 启动有预算：冷启动到首帧 ≤ 1s（本地盘），到可交互 ≤ 2s——超预算即缺陷， CI 打点回归；
3. UI 响应下限：任何操作 ≤ 100ms 必须有可见回执；主 goroutine 与渲染线程禁止阻塞。

## 一、单实例启动（默认）

Wails v3 内置单实例支持——**用框架能力，不自造锁文件**（自造锁有陈旧锁/竞态/清理负担三重坑；安装目录方案中的「单实例锁」条目以本节为准）。

```go
app := application.New(application.Options{
    SingleInstance: &application.SingleInstanceOptions{
        // 第二实例启动时，其命令行参数转发给第一实例
        OnSecondInstanceLaunch: app.SecondInstanceLaunched,
    },
})
```

纪律：

1. **二次启动 = 唤回 + 路由**：聚焦已有窗口；携带的文件/URL 参数路由到正确窗口（路由表 →《窗口与多窗口技术方案》）；托盘唤回与二次启动共用同一路由（→《托盘技术方案》实证复盘）；
2. **参数以结构体传递**：第二实例的 argv 解析成 `SecondInstanceData` 后交给领域层，不透传原始字符串；
3. **多数据目录并存**：`--data-dir` 参数可绕过单实例启动第二实例（开发/测试隔离用），但默认安装路径必须单实例；
4. 第二实例进程**立即退出**（转发完参数即退，不闪烁窗口）。

## 二、快速启动预算（禁止卡顿）

**预算表**（CI 打点回归，超预算即缺陷）：

| 阶段 | 预算 | 内容 |
|---|---|---|
| 进程启动 → 窗口可见 | ≤ 500ms | 创建窗口 + 最小 Go 服务（配置读取、单实例注册） |
| 窗口可见 → 首帧 | ≤ 500ms | 前端骨架渲染（可以仍是加载态） |
| 首帧 → 可交互 | ≤ 1s | 绑定方法可用、首屏数据占位/骨架屏 |
| 冷启动总预算 | ≤ 2s | 本地 SSD 基准 |

纪律：

1. **首帧前只做必需**：窗口创建 + 必须阻塞的首屏状态；其余全部推迟——DB 迁移、自动更新检查、文件扫描、遥测上报一律首帧后异步执行（→《应用状态与持久化技术方案》首帧前后分档表）；
2. **ServiceStartup 禁止慢 I/O**：服务启动返回 error 会中止整个应用——迁移/网络/扫描移到 `ServiceStartup` 之后的 goroutine（受 ctx 治理），界面用就绪标志呈现；
3. **前端骨架先行**：首帧允许是骨架屏，但必须可交互（窗口拖动/关闭立即响应）；
4. **依赖懒加载**：非首屏路由 code-split；大依赖（图表/编辑器 → 集成封装四件套的懒加载模式）动态 import；
5. **启动打点**：进程起 → window shown → 首帧 → 可交互 四个里程碑，debug 构建打印耗时；预算回归进 CI；
6. **禁止启动期卡顿源**：同步大文件读写、全量数据加载、外部进程调用、大图同步解码。

## 三、UI 响应纪律（快速响应操作）

1. **主 goroutine 禁止阻塞**：文件/网络/DB/重计算全部进任务队列或 goroutine（→《长任务与后台工作技术方案》）；Go 侧阻塞会冻结事件分发，前端表现为卡顿；
2. **前端渲染预算**：单帧 ≤ 16ms；长列表虚拟化（→ VirtualList/VirtualizedTree）；大计算移出渲染路径；
3. **操作回执下限**：≥ 100ms 的操作必须有即时反馈（乐观更新 / 进度 / 骨架 / 按钮 loading——loading 纪律 → Button 组件卡）；
4. **防抖节流**：高频输入/滚动/resize 按方案接入（→《防抖与节流方案》）；
5. **取消即响应**：用户取消后 UI 立即回退，后台任务静默收尾（→ 任务队列取消语义）；
6. **卡顿即缺陷**：主线程阻塞 > 200ms、交互无回执 > 300ms 均按缺陷登记，不接受「数据大所以慢」。

## 测试矩阵

| 维度 | 覆盖 |
|---|---|
| 单实例 | 二次启动参数路由到正确窗口；第二进程立即退出；托盘唤回联动 |
| 参数隔离 | `--data-dir` 绕过单实例（开发/测试）可用；默认路径单实例生效 |
| 启动预算 | 四里程碑打点；CI 预算回归；首帧前无慢 I/O（代码审查项） |
| 响应下限 | 绑定方法并发压测（-race）；≥100ms 操作全部有回执（审查项） |
| 卡顿源 | 主 goroutine 无同步 I/O（grep 断言：`os.ReadFile`/`http.Get` 不在事件回调路径） |

## AI 约束模板

> 应用默认单实例启动：二次启动转发参数到首实例并聚焦对应窗口，第二进程立即退出；禁止自造锁文件。启动有预算：首帧 ≤ 1s、可交互 ≤ 2s，首帧前只做窗口创建与最小状态，迁移/更新/扫描全部推迟到首帧后，ServiceStartup 禁止同步慢 I/O；启动四里程碑打点进 CI。UI 响应下限：主 goroutine 禁止阻塞 I/O，重活进任务队列；≥100ms 操作必须有即时回执；长列表虚拟化、高频输入防抖；卡顿 > 200ms 按缺陷登记，不接受「数据大所以慢」。

## 五档定位

- **一档**：单实例默认开启 + 启动打点 + 预算表入 CI；响应纪律写进组件库与服务开发规范；
- **二档**：三平台实机跑预算（WebView2/WebKitGTK/WKWebView 各自基准）；卡顿追踪（长任务面板）上线；
- **持续**：每次新增首帧前工作、新增绑定方法，按本方案预算与纪律自查。
