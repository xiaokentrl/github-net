# 前端目录结构：Wails3 + Go 专用方案

## 这份方案是做什么的

与《后端目录结构方案》成对的前端版。Wails3 的前端是 Vite + 框架（React 等）的 SPA，跑在三引擎 WebView 里。目录结构同样不是审美问题——每个目录对应一条既有纪律的**物理落点**：绑定调用唯一入口、镜像 store、失效订阅中心、错误码映射、IME 安全的输入组件、按路由分割的首帧预算。

两条先说清：

- **生成物与运行时**：wails3 为 Go 绑定生成 TS 代码（输出路径待验证，wails3 模板实测为准），禁手改、CI diff 门禁；前端运行时 API（事件、窗口）经统一封装使用，不散落直接 import（待验证的具体包名随锁定版本）。
- 通用纪律落点：镜像与失效 →《统一同步层技术方案》；组件体系 →《多平台一致组件库方案》；语言包 →《多语言实现方案》；错误码 →《日志与可诊断性技术方案》；持久化边界 →《应用状态与持久化技术方案》。

## 总览

```
frontend/
├── index.html
├── vite.config.ts           # alias（@locales 指仓库根 locales/）、CSP 相关构建配置
├── src/
│   ├── main.tsx             # 入口：只装配（providers + router），业务零容忍
│   ├── app/                 # 应用壳：AppShell、全局 providers、错误边界、主题挂载
│   ├── routes/              # 路由页面：只编排（取 store + 摆组件），无业务逻辑；按路由懒加载
│   ├── stores/              # 镜像 store：按领域切分，与后端 domains/ 一一对应
│   │   └── <domain>.ts      #   镜像读写、乐观更新（settle 状态机）、缓存上限
│   ├── sync/                # 订阅中心：信号→失效→重取、兜底轮询、投影标识注册
│   ├── api/                 # 绑定唯一入口：包装生成绑定，类型化 + 可替换的适配器接缝
│   ├── components/          # 项目业务组件（满足三次规则可提升入库到组件库）
│   ├── ui/                  # 组件库消费层（→ 多平台一致组件库方案，组件卡随库）
│   ├── i18n/                # 语言加载器与响应式 store（语言文件在仓库根 locales/）
│   ├── errors/              # 错误码→文案键映射（与 Go 码表 parity 门）
│   ├── hooks/               # 通用 hooks：每个订阅类 hook 强制成对清理
│   ├── lib/                 # 纯工具：format/（Intl 封装单点）、ids、time——无框架依赖
│   ├── styles/              # 全局样式：令牌消费、reset、字体声明（→ 组件库方案字体决策）
│   └── types/               # 领域类型（与 Go 绑定模型对齐，只放数据容器）
├── bindings/                # wails3 生成 TS：禁手改，CI generate→diff 门禁
└── e2e/                     # Playwright（-tags server 构建，CI 独立 job）
```

## 顶层规则（每条都有为什么）

1. **`api/` 是绑定唯一入口**：全前端只允许此目录 import 生成的绑定，对外提供类型化 hook/函数。这一层同时是主大纲四档「Web/无后端适配器层」的**接缝**——调用收敛到一个接口，未来才可能换适配器；也是错误处理、超时包装、取消句柄（CancellablePromise）的统一挂点。
2. **`stores/` 是镜像，不是事实**：store 只经「api 取数 + sync 失效」改变；乐观更新按固定形状（取消在途 → 快照 → 写入 → 落定从事实源对账），成功路径**不手动转正**。前端永不持久化业务状态——落盘是 Go 侧 `state/` 的事。
3. **`sync/` 是失效订阅中心**：信号类型化注册、按投影标识失效、兜底轮询间隔、焦点/唤醒重查——全部只在这里。组件里不允许出现第二个「自己监听自己刷」的路径；每个订阅与组件生命周期成对清理。
4. **`routes/` 只编排**：页面 = 取 store + 摆组件 + 组装交互，业务逻辑在 stores / hooks；页面级懒加载是首帧预算（→ 性能方案启动路径分解）的实现位置。
5. **`components/` 与 `ui/` 分家**：`ui/` 是组件库（有组件卡、过四件套，跨项目资产）；`components/` 是项目业务组件——第三次出现的业务组件按三次规则评审入库，**不许反向**：业务组件不进库，库组件不带业务。
6. **`errors/` 单点映射**：Go 错误码 → 文案键，码表由单一源生成或有 parity 测试门（→ 可诊断性方案），组件只拿文案键走 `i18n`。

## 各目录职责与对应纪律

| 目录 | 职责 | 落点的纪律 |
|---|---|---|
| `api/` | 包装生成绑定：类型化、输入出口统一、错误转错误码、取消句柄 | 主大纲「Wails 调用包裹在自定义 hook」；四档适配器接缝 |
| `stores/<domain>.ts` | 按领域切分的镜像；领域名与后端 `domains/`、投影标识一一对应 | 同步方案：镜像纪律、领域切分对齐、乐观更新形状 |
| `sync/` | 信号→失效→重取的唯一接线处；兜底轮询；焦点/休眠恢复重查 | 同步方案三通路与「唯一入口」；事件订阅清理 |
| `routes/` | 页面编排 + 懒加载 | 性能方案启动路径；routes 无业务 |
| `components/` | 项目业务组件 | 组件库方案三次规则与回流纪律 |
| `ui/` | 组件库消费 | 组件库方案（组件卡、令牌、引擎基线） |
| `i18n/` | 语言加载器（Vite glob 懒加载）、响应式 locale、`t()` | 多语言实现方案；切换即时生效、lang/dir 更新 |
| `errors/` | 错误码映射 + parity 门消费端 | 可诊断性方案错误码纪律 |
| `hooks/` | 通用 hooks；订阅类 hook 强制返回清理函数 | 同步方案监听器生命周期 |
| `lib/format/` | Intl 封装单点：日期/数字/列表格式化 | 国际化方案「格式化集中展示层」；持久化只存规范化值 |
| `styles/` | 令牌消费、reset、字体栈声明 | 组件库方案令牌纪律（裸值扫描覆盖全局样式） |
| `e2e/` | 端到端 | 主大纲 CI `-tags server` 独立 job |

## 依赖方向（单向，禁止逆行）

```
main/app ──→ routes ──→ stores ──→ sync ──→ api ──→ bindings(生成物)
   │           │          │
   │           └──→ components/ui ──→ stores（只读消费 + 动作调用）
   └──→ i18n / errors / hooks / lib / styles（横向公共层，谁都可依赖）
```

- 只有 `api/` 能 import 生成绑定——grep 审查零例外；
- `stores` 不得 import `routes`/组件（状态层反向依赖视图 = 倒置）；
- `sync/` 不得 import 组件（它只管 store 失效，不直接操作界面）；
- `lib/` 不依赖任何上层（保持纯函数、可独立测试）。

## 命名与禁区

- **禁垃圾包**：`utils/common/misc/helper` 不许出现（与后端同规）；放不进任何目录的能力按「它服务谁」归类。
- store 文件名 = 领域名，与后端领域清单同步增删；新增后端领域 = 新增 store + 在 `sync/` 登记投影标识，两处一起动。
- 组件文件与组件卡同目录（`ui/`），业务组件（`components/`）至少带用途注释与状态说明。
- 包数量克制：小项目 `stores/`、`sync/` 允许单文件起步，出现第二个领域即拆——结构为纪律服务。

## 结构守门清单（验收）

- [ ] 生成绑定的 import 只出现在 `api/`（grep 零例外）
- [ ] store 与后端领域一一对应；投影标识在 `sync/` 登记齐全
- [ ] 全库仅 `sync/` 有信号订阅与兜底轮询；每个订阅有成对清理
- [ ] 乐观更新形状统一（取消在途 → 快照 → 写入 → 落定对账），无「成功转正」
- [ ] `routes/` 页面无业务逻辑；路由级懒加载就位
- [ ] 错误码映射有 parity 门；文案键全走 `i18n`
- [ ] 业务组件未混入 `ui/`；库组件未带业务
- [ ] 无 `utils/common` 包；生成物 diff 门禁在 CI 生效
- [ ] 非 UI 一致性冒烟的前端观察点（各表面收敛）有登记（→ 同步方案）

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 界面不同步 | 组件里散落自己的订阅与刷新 | `sync/` 唯一接线 + grep 审查 |
| 状态闪回旧值 | 乐观更新成功路径手动转正 | settle 状态机统一在 store 动作 |
| 换后端/演示模式伤筋动骨 | 绑定调用散落各组件 | `api/` 唯一入口 = 适配器接缝 |
| 某组件样式改全局崩 | 组件带业务、库与业务组件混放 | `ui/` 与 `components/` 分家 |
| 监听器泄漏越用越怪 | 订阅不成对清理 | hooks 强制返回清理函数 + 审查 |
| 错误提示前后端对不上 | 码表两侧手抄 | `errors/` 单点 + parity 门 |
| 首帧越来越慢 | 页面全量同步加载 | `routes/` 懒加载 + 启动预算 |
| 切语言后一半没变 | 文案绕过 `i18n` 直写 | 文案键全走 i18n + 键齐性门 |
| 重构改名静默错调 | 手改生成物 | CI generate→diff 门禁 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 按本结构落位：生成绑定只在 `api/` import 并做类型化包装；`stores/` 按领域切分且与后端领域对齐，store 是镜像——只经 api 取数与 sync 失效改变，乐观更新按「取消在途 → 快照 → 写入 → 落定对账」的形状，不手动转正；信号订阅与兜底轮询只存在于 `sync/`，订阅与生命周期成对清理；`routes/` 只编排并懒加载；错误码经 `errors/` 映射 + parity 门；文案全走 `i18n`，格式化只在 `lib/format/`；`ui/` 库组件不带业务、`components/` 业务组件不冒充库组件；无 utils 垃圾包；生成物禁手改。新页面/新 store 先定位目录，定位不了先报结构问题。实现后跑结构守门清单，并明确列出未覆盖的组合。

方案确认后再改代码；wails3 前端细节（绑定 TS 输出路径、运行时包名、HMR 行为）以锁定的框架版本实测为准，与本方案冲突时先报告差异再裁决。

## 与既有指南的关系

- 镜像、失效、乐观更新 →《统一同步层技术方案》；store 持久化边界 →《应用状态与持久化技术方案》
- `ui/`、令牌、组件卡 →《多平台一致组件库方案》；语言文件位置与加载 →《多语言实现方案》
- 首帧预算与事件频率 →《性能与资源基线技术方案》；错误码 →《日志与可诊断性技术方案》
- 后端对应物 →《后端目录结构方案》（stores ↔ domains、sync ↔ sync、api ↔ binding）

## 五档定位

- **一档**：结构骨架 + 绑定唯一入口决策（适配器接缝）。
- **二档**：结构守门清单全绿（api 唯一 import、store 与领域对齐、订阅成对清理、生成物门禁）。
- **持续**：新页面/新 store 先定位目录再写代码；守门清单随 CI 常跑。
