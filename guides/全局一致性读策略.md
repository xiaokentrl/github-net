# 全局一致性读策略：通用规划方案

## 这份方案是做什么的

《统一同步层技术方案》管「失效怎么到」（推侧）、《缓存一致性方案》管「缓存什么级别」（存量管理）——但**读侧的决策**没有归属：一次读到底从哪里读？承诺什么新鲜度？陈旧了怎么标记？**多个事实拼成一个视图时会不会撕裂**（订单是新的、客户是旧的）？本方案补上这块：全局一致的读策略。

**硬性目标**：
1. 每个读表面在登记表里声明**读策略与新鲜度承诺**——读路径不靠现场决定；
2. **跨实体组合视图的撕裂有预先选定的策略**（后端聚合 / 版本对齐 / 声明容忍），不默认撕裂；
3. 一切非实时呈现**带新鲜度标记**——陈旧是显式状态，不是假象。

**与相邻方案的分工**：失效信号的到达 →《统一同步层技术方案》《UI数据一致性实现方案》；缓存级别与 key →《缓存一致性方案》（本方案是其「读侧」延伸）；离线降级三档 →《网络与离线弹性技术方案》；写侧一致性 →《原子性提交方案》。

## 核心判定规则

> **这次读的新鲜度承诺是什么？读错了会怎样？**
> 影响决策/金钱/不可逆操作 → **同步直读**；常规展示 → 失效驱动镜像或 SWR；远端缓慢变化 → TTL；断网也要看 → 离线快照。

错配的代价不对称：**把直读降级成 SWR**（决策用了陈旧数据）远比把 SWR 升级成直读（多一次请求）危险——判定拿不准时往直读靠。

## 读策略五型

| 策略 | 语义 | 新鲜度承诺 | 适用 | 呈现 |
|---|---|---|---|---|
| **同步直读** | 现场读权威，等待结果 | 强一致 | 决策点（支付前余额、覆盖前确认） | 等待态显式 |
| **失效驱动镜像** | 平时读镜像，信号到即失效重取 | 收敛时限内一致 | 默认形态（→ 同步层 L1） | 正常呈现 |
| **SWR**（stale-while-revalidate） | 先呈现缓存值，后台刷新到位后替换 | 陈旧 + 刷新中双标记 | 列表回访、非关键路径 | **陈旧标记必须可见** |
| **TTL** | 缓存值 + 过期阈值 | 陈旧窗口 ≤ TTL | 远端元数据、参考数据 | 同上 |
| **离线快照** | 无网络时读最后持久快照 | 明确「截至 X 时刻」 | 离线三档的「只读」档（→ 网络方案） | 截至时刻标记 |

## 跨实体读：撕裂问题（本方案独有的深水区）

单事实的一致性已被同步层解决；**多个事实拼成一个视图**（订单 + 客户 + 库存）时，各事实独立失效、独立重取——组合视图可能出现**版本撕裂**。三条策略，按成本递增：

1. **后端聚合投影（首选）**：组合会被用户当作「一个事实」的（订单详情 = 订单 + 客户 + 明细），由**后端一个聚合接口返回一致快照**——服务端在单事务/单快照内组装，天然无撕裂；同时减少信号风暴（一次失效覆盖整个投影）。聚合投影同样登记唯一读取口（→ 同步层纪律）。
2. **前端版本对齐**：确需前端拼装时，各事实带版本号，**组合视图取各事实版本的公共基线**——任一事实版本低于基线即整体进入刷新态，不许新旧混排。
3. **声明容忍**：确定撕裂无害（各事实用户视角独立），登记撕裂窗口与标记，评审通过。

**判定规则**：把组合视图里的两个字段问一句「**用户会把它们当成一个事实吗？**」会 → 聚合投影；不会 → 各自读 + 容忍。

## 陈旧标记纪律

- SWR / TTL / 离线快照的呈现**必须带新鲜度标记**（「更新中…」「截至 10:24」「离线数据」）——标记是读策略的组成部分，不是可选美化；
- 标记由数据层给出（`isStale` / `asOf`），**不由组件自行判断**——组件没有判定依据（→ 缓存方案「前端不自行判过期」同一条）；
- 标记样式全库统一（→ 组件库方案 Badge/Text 第二通道）。

## 读路径登记表（缓存登记表的读侧扩展）

| 读表面 | 数据 | 策略 | 新鲜度承诺 | 陈旧标记 | 刷新时机 |
|---|---|---|---|---|---|
| 例：订单详情页 | 订单聚合投影 | 直读 → 镜像 | 落定即一致 | 无 | 信号 + 兜底 |
| 例：联系人回访列表 | 客户列表 | SWR | 陈旧 ≤ 1 次刷新 | 「更新中」角标 | 挂载后台刷 |
| 例：汇率 | 远端参考 | TTL 5min | ≤ 5min | 无（容忍） | TTL 到期 |

**登记表外不建读路径**——与缓存登记表同一条宪法。

## 多窗口与离线

- 各窗口独立执行同一读策略；收敛靠信号（→ 同步层多窗口纪律）——SWR 的陈旧窗口在多窗口下同样成立，写进新鲜度承诺；
- 离线时：直读策略降级为「明确禁用或只读快照」（→ 网络方案离线三档），**不悄悄换成 SWR 假装在线**。

## 测试矩阵

| 维度 | 要覆盖的情况 |
|---|---|
| 撕裂 | 两事实先后变更 → 组合视图按登记策略呈现（聚合无撕裂 / 对齐进入刷新 / 容忍有标记） |
| SWR | 首帧陈旧 + 标记可见、后台刷新后替换、刷新失败保留陈旧 + 错误呈现 |
| 直读 | 决策点走直读；等待态呈现 |
| 降级 | 离线时直读/SWR 各自按登记降级，无「实时假象」 |
| 多窗口 | 双窗口同策略，陈旧窗口一致 |
| TTL | 边界（过期前后一读之差） |

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 详情页一半新一半旧 | 跨实体各自读、无对齐策略 | 聚合投影 / 版本对齐 / 容忍声明 |
| 用户按陈旧数据做了决策 | 决策点用 SWR/TTL | 新鲜度承诺判定 + 直读分级 |
| 回访列表闪旧数据、用户以为实时 | SWR 无标记 | 标记由数据层给出 |
| 离线看到「实时」假象 | 快照无截至标记 | 离线快照标记 |
| 组合接口成了第二个事实源 | 聚合投影未登记读取口 | 唯一读取口纪律延伸 |
| 刷新风暴 | 每表面各自 SWR 无节流 | 刷新时机进登记表 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 先给出读路径登记表（表面 × 数据 × 策略 × 新鲜度承诺 × 标记 × 刷新时机）。每读按判定表归类，决策点必须同步直读；跨实体组合先答「用户是否当作一个事实」，聚合投影在后端组装并登记唯一读取口，前端拼装必须版本对齐或声明容忍；SWR/TTL/离线呈现一律带数据层给出的新鲜度标记，组件不自判；离线时直读策略显式降级不假装在线。实现用统一钩子（→ lib/read），不各写各的 fetch 逻辑。实现后补撕裂注入、SWR 首帧标记、离线降级与多窗口的测试，并明确列出未覆盖的读表面。

方案确认后再改代码；新鲜度承诺属产品决策（哪些页面允许陈旧），AI 给推演，最终由用户裁决。

## 五档定位

- **一档**：读路径登记表初稿 + 新鲜度承诺分级 + 撕裂策略判定。
- **二档**：SWR/TTL/直读钩子落地、标记组件接线、聚合投影接口设计。
- **三 / 四档**：撕裂注入测试、离线降级全量、多窗口一致性全测。
