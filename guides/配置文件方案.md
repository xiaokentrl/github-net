# 配置文件：Wails3 + Go 专用方案

## 这份方案是做什么的

配置文件是《应用状态与持久化技术方案》中「设置」类状态的**具体载体**。状态方案定了纪律（唯一写入口、原子写、schema 版本与迁移、损坏降级三选一）；本方案回答落地决策：**有哪些配置文件、用什么格式、schema 放哪、错了怎么报、人能不能手改、文档从哪来**。

**定位**：配置文件是用户与程序之间**可读可改的合同**——程序要唯一写入口地管理它，高级用户也要能打开手改。两边都要成立，冲突处必须显式决策，不许默认。

硬性底线（继承状态方案）：原子写、默认值单源、版本号进文件、损坏不静默、敏感值永不进配置文件。

## 文件清单（先分家，再谈格式）

| 文件 | 内容 | 谁写 | 手编辑 |
|---|---|---|---|
| `settings.toml` | 用户设置（全部「设置」类状态） | 程序经唯一写入口；用户可手改 | ✅ 目标 |
| 凭据存储 | 令牌、密钥 | 程序独占，权限 0600 | ❌ 永不进设置文件（→ 状态方案敏感类、安全方案） |
| 数据库等数据文件 | 业务事实 | 程序独占 | ❌ 不是配置 |
| 导出的 profile | 用户主动导出的设置快照 | 用户触发 | 可选，用于迁移/支持 |

**分离规则**：手编辑友好性、敏感性、数据量是三个正交维度——设置（小、可手改）与数据（大、程序独占）与凭据（敏感）**永不混在一个文件里**。诊断包只带配置的结构化摘要并排除敏感键（→ 可诊断性方案）。

## 格式决策

| 格式 | 手编辑 | 注释 | 程序读写 | 结论 |
|---|---|---|---|---|
| TOML | 好 | ✅ | Go 生态成熟（BurntSushi 等） | **用户设置推荐** |
| JSON | 一般 | ❌ | 最普遍 | 程序管理的数据、导出交换 |
| YAML | 看起来好 | ✅ | 缩进地狱、隐式类型坑（挪威问题） | 不推荐新用 |

一个必须显式决策的冲突——**程序重写会抹掉用户注释**：多数序列化库 marshal 时不保留注释（具体库能力待验证）。三选一并记录：

1. 接受丢失（最常见，写进文档告知）；
2. 最小重写（只改动变化的键，需库支持或精细实现）；
3. 设置拆两个文件：程序高频写的（窗口几何类自动状态）用 JSON，用户手编的偏好用 TOML——注释永不被程序碰。

## Schema 单源：Go struct 是一切的开端

- **Go struct + tag = schema 单源**：字段定义、`default`（默认值唯一源 → 状态方案）、校验规则、生效方式（`reload=immediate|restart`）、文档注释，全部标在 struct 上。
- **生成物一鱼三吃**：
  1. **JSON Schema** → 写进配置文件头部 `$schema` 字段，编辑器即得补全与实时校验；
  2. **Markdown 配置文档** → 随版本生成入库，文档永不与实现漂移；
  3. **校验器** → 运行时与 CLI 共用（CLI 能离线校验用户配置，→ 后端结构方案 `cmd/cli/`）。
- 文件带 `version` 字段；迁移函数挂 schema（→ 状态方案迁移纪律，降级明确拒绝）。

## 校验与报错（对「手改坏了」要友好）

- **全部错误一次报完**：不逢错即停，收集所有问题一次性呈现；每条带文件:行号、键路径、期望 vs 实际。
- **逐键降级**：单个键非法 → 该键回默认值 + 明确提示，其余键照常生效；**不许静默吞**（状态方案损坏降级在键级的应用）。
- **未知键**：按「疑似拼写错误」警告并保留在文件里（不因程序不认识就删用户的注释与键——丢弃策略须显式决策）。
- 解析级损坏（截断、非法语法）→ 走状态方案的损坏降级三选一（保留坏文件、用默认值、提示）。

## 手编辑支持

- 文件内 `$schema` 指向生成的 JSON Schema（编辑器自动补全的前提）。
- 应用内提供「打开配置文件」「打开配置目录」入口（定位到 `paths/` 管理的实际路径）。
- **生效方式逐键声明**（schema tag）：`immediate` 的经变更信号即时生效（设置变更广播给 Go 与前端——与《多语言实现方案》语言切换同一条链路，→ 同步层）；`restart` 的在文档与 UI 中注明。
- 是否监听文件变化（外部手改后热生效）：立项显式决策；启用则 watcher 归 `state/`，外部改动走与程序改动相同的信号链，不另开旁路。

## 写入纪律（继承状态方案，逐条落名）

- 唯一写入口 = `state/`（→ 后端结构方案）；其他任何包不许开配置文件。
- 原子写（临时文件 + 改名）；变更即写或去抖带上限。
- 程序写盘前 normalize：按 schema 补默认、按策略处理未知键、版本号更新。
- **敏感值审查**：设置文件入库模板与 CI 检查确认无令牌/密钥字段（它们在凭据存储里）。

## 路径与搬家

- 平台标准目录由 `paths/` 统一（config/data/cache 分离、权限收紧 → 后端结构方案、状态方案）。
- 旧版配置**一次性搬家**：新位置没有而旧位置有才搬，原件保留（主大纲「配置路径与迁移」条目）。

## 验收清单

- [ ] 首次启动行为明确：惰性创建（首次写入才建文件）或生成带注释的示例文件——二选一已记录
- [ ] 手改出错的文件：逐键降级 + 一次报完 + 行号定位，应用照常启动
- [ ] 编辑器补全可演示（`$schema` 生效）
- [ ] 配置文档由 schema 生成，与实现零漂移
- [ ] 跨版本迁移与降级拒绝各有测试
- [ ] 旧路径搬家演练通过、原件保留
- [ ] CLI 可离线校验配置文件
- [ ] 敏感值 grep 审查通过

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 用户注释被程序抹掉 | 整文件重写无保留策略 | 三选一显式决策 |
| 配置写错应用静默回默认 | 无校验报告 | 逐键降级 + 一次报完 |
| 文档说的键实际不存在 | 文档手写 | schema 生成文档 |
| 编辑器没有补全 | 未生成 JSON Schema | `$schema` + 生成链 |
| 秘钥进了设置文件 | 无分离清单 | 凭据分离 + CI 审查 |
| 改了配置没反应也不知要重启 | 生效方式未声明 | schema tag 逐键标注 |
| 升级后配置丢失 | 无版本迁移 / 无搬家逻辑 | version + 迁移函数 + 搬家演练 |
| 两个包各自读写配置 | 无唯一写入口 | `state/` 独占 + grep 审查 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 配置以 Go struct + tag 为 schema 单源，默认值、校验、生效方式、文档注释全标在 tag 上；由它生成 JSON Schema（进文件 `$schema`）、Markdown 文档与校验器，三者不手写。用户设置用 TOML，注释重写策略三选一显式决策；程序读写只经 `state/` 唯一入口，原子写，敏感值永不入此文件。加载失败逐键降级、全部错误一次报完并带行号；未知键警告并保留；版本号进文件，迁移函数带测试，降级明确拒绝；旧路径搬家一次性且原件保留。生效方式逐键声明，immediate 项走统一变更信号。实现后跑验收清单，并明确列出未覆盖的组合。

方案确认后再改代码；序列化库的注释保留能力等以锁定版本实测为准，先验证再决策。

## 与既有指南的关系

- 纪律母法（唯一写入口、原子写、迁移、损坏降级、敏感分离）→《应用状态与持久化技术方案》
- 写入口位置 →《后端目录结构方案》`state/`；变更信号 →《统一同步层技术方案》
- 语言等设置的即时生效链 →《多语言实现方案》；诊断包中的配置摘要 →《日志与可诊断性技术方案》
- 路径与目录 →《后端目录结构方案》`paths/`；打包期配置 →《签名打包与更新分发技术方案》

## 五档定位

- **一档**：文件清单与分离决策、格式与注释重写策略三选一（大纲准入条目在二档「配置路径与迁移」）。
- **二档**：schema 单源与生成链（Schema / 文档 / 校验器）、逐键降级、迁移与搬家。
- **三 / 四档**：热生效 watcher、CLI 离线校验、敏感值 CI 审查全量。
