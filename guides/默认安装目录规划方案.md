# 默认安装目录规划：Wails3 + Go 专用方案

## 定位与硬性目标

母法方案：《签名打包与更新分发技术方案》。母法管「签名、打包、更新与回滚」；本方案管**文件住址**——程序、数据、缓存、日志在三大平台的唯一归属，以及安装根的解析规则。姊妹方案：《版本号方案》（版本号单源）、《发布交付流水线方案》（交付链操作序列——本方案的目录契约是其中「出包/安装」两步的输入）。

**硬性目标**：

1. 目录契约单源：全部路径由唯一模块按平台推导，代码中禁止出现硬编码路径字符串；
2. 分类集中：每类文件有且仅有一个归属目录，任何文件不得落在契约之外；
3. 只读程序区：安装目录在运行期只读——数据、缓存、日志一律不写入；
4. 卸载即净空：卸载器能按契约枚举并清除全部落地文件，无残留。

## 核心原则：分类集中，而非单目录混装

「全部资源集中存放」的正确实现是**每类文件一个唯一归属**，不是把所有东西塞进安装目录：

- macOS：写入 `.app` 包内会破坏代码签名，更新即失效；
- Windows：`Program Files` 受 ACL 保护，写数据撞权限；多用户共用安装目录时数据互相覆盖；
- Linux：写 `/opt` 违反 FHS（只读程序区），卸载不净。

**「乱扔文件」的黑名单**（每一条都是真实软件踩过的坑）：

| 反模式 | 危害 |
|---|---|
| `$HOME/.软件名` 裸点目录 | 家目录污染，用户最反感的形式 |
| 数据写在 exe 旁边 | Windows ACL 拒写 / 多用户互踩 / 签名失效 |
| 配置散落注册表各处不集中 | 无法备份、无法卸载净空 |
| 缓存写进数据区 | 备份膨胀、数据目录不可预期 |
| 日志写进程序目录 | 磁盘涨满且更新时被连带清除 |
| 硬编码 `C:\`、`D:\`、`/usr/share` | 换机器即坏 |

## 目录契约：六类文件 × 三平台

约定 `<AppName>` = 安装器/包名（如 `软件名`），`<BundleID>` = 反向域名（如 `com.company.appname`），`<Company>` = 公司名。**BundleID 是 macOS 的目录命名权威**（非中文软件名）。

**主根（单根集中）**：用户数据 / 配置 / 日志三区同根——用户备份、卸载、排障只看一个目录。**唯一例外是缓存**：系统清理工具（Windows 磁盘清理、macOS 存储管理、Linux ~/.cache 清理）只认平台缓存目录，缓存并入主根会让这些工具全部失效，故单列。

约定 `<AppName>` = 安装名，`<BundleID>` = 反向域名，`<Company>` = 公司名。**BundleID 是 macOS 的目录命名权威**（非中文软件名）。

| 类别 | Linux | Windows | macOS |
|---|---|---|---|
| **主根** | `~/.local/share/<app>/` | `%LOCALAPPDATA%\<Company>\<AppName>\` | `~/Library/Application Support/<BundleID>/` |
| └ 配置 | `<主根>/config/` | `<主根>/config/` | `<主根>/config/` |
| └ 用户数据 | `<主根>/data/` | `<主根>/data/` | `<主根>/data/` |
| └ 日志 | `<主根>/logs/` | `<主根>/logs/` | `<主根>/logs/` |
| **缓存（唯一外置）** | `~/.cache/<app>/` | `<主根>/Cache/`（LOCALAPPDATA 不漫游，可内联） | `~/Library/Caches/<BundleID>/` |
| **程序区**（只读） | `/opt/<AppName>/` 或 `~/.local/opt/<AppName>/` | 安装根（运行期 `os.Executable()` 推导，零注册表） | `/Applications/<AppName>.app` |
| **可执行入口** | `/usr/local/bin/<app>` 或 `~/.local/bin/<app>` 符号链接 | 安装根内 exe + 快捷方式 | `.app` 内置 |
| **临时文件** | `$XDG_RUNTIME_DIR/<app>/` 或 `/tmp` | `%TEMP%\<AppName>\` | `$TMPDIR` |
| **共享/机数据** | `/var/lib/<app>/`（仅系统服务） | `%ProgramData%\...`（仅 per-machine 需要时） | `~/Library/Group Containers/<GroupID>/`（仅套件共享） |

> per-user 安装（Linux/Windows 免提权档）只是程序区换位置，数据主根不变。

**旧四分契约（XDG 原教旨：share/config/cache/state 各一处）保留为备选档**——仅当产品明确要进 Linux 发行版官方仓库（打包者要求遵守 FHS/XDG 原教旨）时切换，桌面自分发产品默认用上表单根契约。

> 上表即**目录契约**。每一格的完整路径有且仅有一个；全部由单源模块推导（见下），契约之外的任何写操作都是缺陷。

## 三平台安装根解析

### Linux：`/opt/<AppName>/`（产品默认，符合 FHS）

- 多用户自包含安装：程序文件全部进 `/opt/<AppName>/`（FHS 3.0 §3.13：第三方自包含软件的指定位置）；`/usr/local/bin/<app>` 放符号链接供命令行调用；
- 可变数据：服务端场景才用 `/var/opt/<AppName>/`，桌面应用一律走用户 XDG 目录；
- **per-user 安装**（无 sudo）：整棵树迁到 `~/.local/opt/<AppName>/` + `~/.local/bin` 链接；
- 卸载：删 `/opt/<AppName>/` 与符号链接即净（用户数据在契约目录，由卸载器按用户确认清除）。

### Windows：安装根解析链（安装器执行，结果持久化）

产品要求「默认安装到 `D:\软件名`」——正确编码方式是**默认优先级解析链**，而非硬编码盘符（无 D 盘的机器即坏）：

```
安装根解析链（安装器逐步求值）：
1. **用户指定目录：绝对遵从**——校验（可写、空间、文件系统）通过即用；**绝不静默重定向**。校验失败时给出明确原因与修复建议，由用户改选，安装器不替用户做主
   - 仅有的拒绝条件：指向系统保护区（如 C:\Windows 内部）或非法路径——报错并说明，仍由用户改选
   - 空间不足/权限不足 → 明确报错让用户处理，而非偷偷换地方
2. 用户未指定时的产品默认：D:\软件名（条件：D: 存在 ∧ NTFS ∧ 剩余空间 ≥ 500MB）；不满足则回退 %LocalAppData%\Programs\软件名（免提权）；企业 per-machine 场景 %ProgramFiles%\软件名（需提权）
3. 用户选择持久化（数据区 `config/install.json` + 安装器记忆），下次升级/更新默认沿用
```

- 解析结果持久化：安装根写入数据区 `config/install.json`（文件形式，零注册表）；运行期同时以 `os.Executable()` 实时推导兜底——两者不一致时以 exe 实际位置为准（防目录被手动移动）；
- **运行期零注册表**——安装器与运行期都不写注册表（见「注册表零写入」节）；
- 更新器写安装目录时以安装根 ACL 为准：per-user 安装无需提权，per-machine 更新需提权或使用更新服务。

## 注册表零写入（Windows 红线，默认）

**默认安装/运行/更新/卸载全流程不写任何注册表值**——全部场景都有文件级等价物：

| 触点 | 注册表方案（弃用） | 零注册表替代 |
|---|---|---|
| 卸载列表登记 | `UninstallString` 键 | **应用内卸载器**：设置页「卸载」+ 安装目录内 `uninstall.exe`，按 manifest 反向执行 |
| InstallPath 持久化 | ~~`InstallPath` 键~~ | 运行期 `os.Executable()` 天然推导；更新器由主程序拉起并传参，无需查询 |
| 自启动 | `HKCU\...\Run` 键 | **启动目录 .lnk 文件**（`shell:startup`）——文件形式，卸载即删 |
| 快捷方式 | — | 开始菜单/桌面 `.lnk` 本身就是文件（非注册表） |
| 文件关联 | `HKCU FileExts` | 唯一无文件级等价物的场景 → **默认不装**；显式同意才写（唯一注册表例外） |
| PATH | 注册表直写 | 用户级环境变量经 `setx` 亦是注册表 → 改为**随包附带启动脚本**或 opt-in 显式同意 |

**代价与缓解**：不写卸载键 → Windows「设置 → 应用」列表看不到本软件。缓解：安装完成页/设置页/安装目录内三处显式卸载入口；opt-in「登记到系统卸载列表」勾选项（写且仅写一个 Uninstall 键）供需要的用户。

**唯一注册表例外（仍需显式同意）**：文件关联（`HKCU FileExts`）——Windows 无文件级等价机制。

## 安装清单与目录结构可视化（所写即所录）

**所写即所录**：安装器触碰的每一个文件、每一个注册表值、每一个快捷方式，**创建时即记入清单**——卸载、修复、审计以清单为唯一依据，不靠事后扫描猜测。

1. **`manifest.json`**（写入安装根，机器可读）：全部落地文件的相对路径 + SHA256 + 用途标注（程序/文档/数据）+ 创建来源（安装器/更新器/运行期）；
2. **`目录结构.txt`**（人类可读版）：树形缩进 + 每个目录的用途注释，安装完成即生成；
3. **安装完成页**：渲染目录树 + 「打开安装目录」「打开数据目录」按钮；
4. **运行期可查**：设置 → 「存储位置」页（各目录路径 + 打开按钮）；CLI `<app> paths` 输出全部位置；
5. **卸载 = 反向执行清单**：按 manifest 删文件 → 删快捷方式/注册表值 → 运行期新增文件（不在清单）按用户选择处理；
6. **完整性**：每次启动校验 manifest 哈希（抽查）——被篡改/损坏可在设置页一键修复。

## 数据目录自定义（聚合模式，高级选项）

- **默认（契约模式）**：主根三区（config/data/logs）+ 平台缓存目录外置——OS 清理工具友好；
- **聚合模式（安装器「数据目录」高级选项）**：用户指定目录后，**四区全部收进一个目录**——

```
<用户指定的数据目录>/<AppName>/
├── config/    ← 配置
├── data/      ← 用户数据
├── cache/     ← 缓存（聚合后由应用自管）
└── logs/      ← 日志
```

- 用户备份/迁移/卸载**只看这一个目录**——「全部资源集中存放」的完全体；
- paths 模块读取用户覆盖并持久化（安装器写入数据区 `install.json` 同级的 `DataRoot` 覆盖值），运行期永不重算；
- **配套义务：缓存自管理**。聚合后 OS 清理工具不再管理缓存，应用必须自带上限策略（LRU / 容量上限，默认 500MB，设置页可见可清）——否则缓存无界增长就是另一种「乱拉屎」；
- **两层控制权分离不变**：程序区绝对遵从用户指定；数据区默认契约、聚合模式可选——控制权给用户，机制不破坏。

### macOS：`/Applications/<AppName>.app`（唯一正确答案）

- 安装 = 把 `.app` 拖入 `/Applications`（DMG 内放 Applications 快捷方式引导），**没有「选择安装目录」的惯例**——用户硬要放别处，Gatekeeper 隔离属性与Launchpad 体验都会劣化，方案明确不做；
- 数据全走 `~/Library` 家族（见契约表），命名用 `<BundleID>`（反向域名），**绝不用中文名**（工具链对非 ASCII 目录名的兼容性不可控）；
- **红线：运行期对 `.app` 包内零写入**——任何写入都会破坏代码签名，导致更新后失效或 Gatekeeper 拒启；
- 沙盒化（未来上架 App Store 时）：目录自动迁移到 `~/Library/Containers/<BundleID>/`，由 `FileManager` 标准 API 解析——paths 模块预留沙盒分支即可，无需改契约。

## 开发期与安装期：双模式路径解析

**开发期一律使用相对路径**——`wails dev` 的工作目录就是项目目录，数据落在项目内 `dev-data/`，与安装期契约路径彻底分离：

| 模式 | 触发条件 | 路径形态 | 适用 |
|---|---|---|---|
| **开发模式** | 无 `install.json`（未安装）∨ 环境变量 `APP_ENV=dev` | **相对路径** `./dev-data/{config,data,cache,logs}` | `wails dev` / 直接运行构建产物 |
| **安装模式** | 安装器写入的 `install.json` 存在 | 契约绝对路径（/opt、Program Files、Application Support） | 已安装的正式版本 |

判定顺序：环境变量显式指定 > `install.json` 存在（安装模式）> 开发模式兜底。**模式判定本身也在 paths 模块内单源**，调用方无感知。

开发模式的价值（与「禁止乱扔文件」同源）：

1. 开发不污染机器全局目录——`wails dev` 每次运行的数据都落在项目内，删项目目录即完全清理；
2. 多份工作区/多分支互不干扰——每份 clone 有独立 dev-data；
3. 测试隔离天然成立——测试数据不与真实安装数据混合；
4. 新人克隆即跑——无需先安装任何系统级目录。

**与发布交付流水线衔接**：《发布交付流水线方案》「重装验证」步骤以安装模式验契约绝对路径；开发期验相对路径。两条路径在同一方案下定义、同一模块解析。

## 单源实现：paths.go（唯一路径推导模块）

```go

    ConfigDir  string // <AppRoot>/config
    DataDir    string // <AppRoot>/data
    LogDir     string // <AppRoot>/logs
    CacheDir   string // 缓存（开发模式 = <AppRoot>/cache 同根；安装模式 = 平台缓存目录，唯一外置）
    InstallDir string // 程序区（仅安装模式有值；开发模式 = 工作目录本身）
    TempDir    string // 临时
}

func Resolve(appName, bundleID, company string, dataRootOverride string) Layout {
    // 模式判定（单源）：APP_ENV=dev 显式 → 开发模式；
    //   否则 install.json 存在 → 安装模式；否则 → 开发模式兜底
    //
    // 开发模式：AppRoot = "./dev-data"（相对工作目录），四区同根——删项目目录即完全清理
    //
    // 安装模式：
    //   聚合（dataRootOverride 非空）：四区收进 <override>/<app>/
    //   契约（override 为空）：
    //     主根：Linux ~/.local/share/<app> ｜ Windows %LOCALAPPDATA%\<Company>\<App> ｜ macOS ~/Library/Application Support/<BundleID>
    //     缓存：Linux ~/.cache/<app> ｜ Windows <AppRoot>/Cache ｜ macOS ~/Library/Caches/<BundleID>
    //     InstallDir：Windows = os.Executable() 所在目录（安装器写 config/install.json 兜底）；macOS 由 main bundle 推导；Linux /opt 或 ~/.local/opt
}

// Windows 专属：安装根推导（零注册表）
func windowsInstallRoot(company, app string) string { /* os.Executable() 优先；config/install.json 兜底（安装器写入） */ }
```

**纪律**：

1. 全库引用 `paths.Resolve()` 的返回值，`grep` 断言：除 paths.go 与安装器外，`*.go` 中不得出现 `Program Files`、`AppData`、`/opt/`、`Application Support` 字面量；
2. 每个目录首次使用前 `MkdirAll`，权限 Linux `0o755`、数据文件 `0o600`；config/data/logs 三区必须同根；**聚合模式下缓存也在主根内**（OS 清理工具不覆盖 → 应用必须自带缓存上限清理，默认 500MB LRU，设置页可见可清）；
3. 临时文件用完即删，退出时兜底清理；
4. **模式判定单源**：开发/安装双模式的判定只存在于 paths.Resolve 内部，业务代码禁止自行判断（如读 APP_ENV、探测 install.json）——调用方只拿 Layout 结果。

## 更新与卸载的目录契约义务

- **更新**（→ 母法）：只替换程序区；数据/配置结构变更走迁移（版本号驱动，向后兼容一档）；更新器对程序区的写入用安装器同等 ACL；
- **卸载**：按契约反向枚举——程序区必删；用户数据/配置**默认保留**（用户可能重装），提供「同时删除个人数据」显式选项；缓存/日志/临时必删；
- **迁移**：目录布局变更是版本化事件——旧布局检测 → 原子迁移 → 旧目录留 `MIGRATED` 标记（一个空文件即可），失败可回退；
- **dry-run 两步模式（plan-then-apply）**：卸载/清理/迁移均支持 `--dry-run`——先产出完整变更计划（将删/将移/将迁的清单），用户确认后一次应用。**删除与移动类操作必须自带此两步**：afero 的 CopyOnWriteFs 实证表明，仅创建/覆盖类命令的 dry-run 是免费的，而删除/移动类会"报成功实未删"——必须显式 plan-then-apply（→ afero 技能 MIT，Steve Francia）；
- **可信根 + 不可信部分**：用户指定的安装根是可信根；用户输入的文件名/ID/抓取标题是不可信部分——拼接前消毒（非法字符、保留名、跨盘逃逸），并保证结果不逃出可信根（防 `../` 与绝对路径注入）。Go 实现建议引入 `spf13/pathologize`（消毒+围堵）与 `spf13/fileflow`（跨盘安全移动），或等价自实现并测试（→ fileflow-pathologize 技能 MIT）。

| 中文/空格路径 | Windows 安装到含空格与中文名目录，全部功能可用 |
| 注册表零写入 | 装后扫注册表（HKCU/HKLM 全量）：与本软件相关键数 = 0；显式同意的文件关联与卸载登记（opt-in 勾选）除外 |
| manifest 完整性 | manifest 列表 == 磁盘实际文件集（含哈希）；删除一个文件后完整性校验报损 |
| 用户指定只读目录 | 指向只读路径时明确报错不重定向；指向系统保护区时拒绝并说明 |
| 自启动/关联同意 | 默认装后无自启动、无文件关联；显式勾选后才有，卸载即除 |
| 聚合模式缓存上限 | 缓存写到容量上限后 LRU 淘汰最旧；设置页「清空缓存」即时生效且不影响 data |
| 聚合/契约切换 | 两模式互切时旧目录数据自动迁移到新模式位置；失败可回退 |
| 预览门禁 | 树未渲染完成时「下一步」禁用；跳过预览页（向导回退再前进）仍强制展示 |
| 调整生效 | 预览中改数据根/子目录位置 → 实际安装落位与预览树逐节点一致；manifest 以确认树为蓝本 |
| 冲突标红 | 目标已有文件/无写权限 → 节点标红 + 下一步禁用；修正后恢复 |

## 安装前预览：目录结构图强制门禁（所见即所写）

**规则：预览页未确认，安装不得开始。** 「下一步」按钮在目录树渲染完成前禁用；任何位置调整后树实时重渲染，确认以最终树为准。

### 预览页内容（实时推导，不读磁盘——装前磁盘上还没有）

- 树根两棵：程序区 + 数据区（聚合模式则一棵），每节点标注：类别图标（程序/数据/缓存/日志）、用途说明
- 程序区内部文件折叠为计数节点（`程序文件 × 214`），关键入口（主程序 / uninstall.exe）可展开
- 底部统计：总目录数 / 总文件数 / 预计占用空间

### 中途任意调整

- 点任何目录节点 → 改该节点位置（含移动到其他盘/目录），子树实时跟随刷新
- 改根 → 整棵树重排；冲突（目标已有文件 / 无写权限 / 非法路径）**即时标红该节点并禁用下一步**，修正后恢复
- 调整记录进「变更列表」，确认后一次生效（不逐个落盘）

### 确认与落盘

- 「开始安装」= 确认当前树 → 安装器按树逐节点创建 → **manifest 以确认树为蓝本生成**
- 所见 = 所确认 = 所写 = manifest，四者一致（可视化门禁是「所写即所录」的前置环节）

## AI 约束模板

> 实现任何文件读写时，必须从 `paths.Resolve()` 获取目录，禁止硬编码路径或在 exe 目录旁创建文件；新文件类型出现时先登记进目录契约表再实现；Linux 遵守 FHS/XDG，Windows 区分 per-machine/per-user 并将安装根写入数据区 install.json（零注册表），macOS 数据走 `~/Library` 家族、命名用 BundleID、对 `.app` 包内零写入；**注册表零写入（默认）：自启动走启动目录文件、文件关联默认不装（显式同意才写 FileExts——唯一例外）、系统卸载列表登记为 opt-in**；**安装器遵守「所写即所录」：每个触碰的文件/键/快捷方式创建时记入 manifest，卸载反向执行**；**用户指定安装目录绝对遵从，校验失败明确报错不静默重定向**；**安装器必须提供装前目录结构预览门禁——树由契约与用户选择实时推导，未确认不得开始安装，中途可任意调整位置且树实时刷新，确认树即 manifest 蓝本**；实现后运行路径单源 grep 断言、注册表白名单扫描与三平台矩阵，任何契约外写入视为缺陷。

## 契约落地实现（packaging/）

三平台安装器/打包脚本已按本契约实现：[`packaging/`](../../packaging/README.md)

- **Windows NSIS**（packaging/windows/installer.nsi，NSIS 3.10 编译验证）：解析链、预览门禁页、注册表零写入、manifest 递归枚举、一体化卸载器
- **macOS DMG**（packaging/macos/make-dmg.sh）：/Applications + `~/Library` 契约目录预生成 + 签名公证提醒
- **Linux install.sh**（packaging/linux/install.sh）：manifest 驱动安装/卸载（冒烟测试通过）、XDG 数据根、.desktop 入口
- **Linux AppImage**（packaging/linux/make-appimage.sh）：聚合模式便携形态

契约变更只改本方案与契约表，三平台脚本同步。

## 五档定位

- **一档**：目录契约表 + paths.go 单源模块 + 解析链规则，作为安装器与运行期的强制约定；
- **二档**：三平台安装器落地契约（NSIS/DMG/deb 或 AppImage），卸载器按契约净空；
- **持续**：新文件类型先登记契约再实现；契约外写入进 CI 断言。
