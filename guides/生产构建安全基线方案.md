# 生产构建安全基线方案：通用规划方案

## 这份方案是做什么的

来源：主大纲二档「安全与外部接口」整节（MCP/Agent 控制接口、生产 DevTools 禁用、生产 CSP 注入、Go 侧 HTTP 客户端与系统代理/PAC），以及 OWASP 桌面应用安全里的「安全配置错误」「不足的日志与监控」两类。

母法方案：《安全边界与权限技术方案》（信任边界与 CSP）、《本地敏感数据与密钥管理方案》（TLS 与证书校验）、《网络与离线弹性技术方案》（代理策略）、《Wails3框架版本判别与服务纪律方案》（版本与 tag）、《CI矩阵与质量门禁方案》（门禁）、《签名打包与更新分发技术方案》（签名与发布）。

它管**「开发态与生产态的差」**：哪些能力只在开发构建存在、生产构建必须显式关闭或显式注入、由哪一道 CI 门证明。失败模式很固定——本地调试方便留下的开关，悄悄跟着发布包到了用户机器上。

不预设：框架小版本、CSP 具体指令、tag 名、代理策略。未核实的行为标**待验证**。

## 开始写代码前，先让 AI 回答这些问题

1. 生产构建是否显式禁用 DevTools/Inspector？**是显式配置项，还是依赖「默认关」**？
2. 锁定框架版本里该配置项的准确名字与默认值是什么？升级后是否复核（→《Wails3框架版本判别与服务纪律方案》）？
3. 生产 CSP 由谁注入？走 `assetserver` 中间件还是构建期注入？策略至少包含哪些指令？
4. CSP 是否在**目标 WebView** 里实测过生效（不是只看代码里写了）？三平台 WebView 对指令的支持差异是什么？
5. 框架是否内置 Agent/MCP 控制接口（构建 tag 开启）？生产构建是否明确不带该 tag，并有「生产产物不含该能力」的门禁？
6. 若未来要在生产启用远程诊断，认证层与网络暴露审查是什么（主大纲五档已把「MCP 生产启用」列为暂缓，需带触发条件）？
7. Go 宿主 HTTP 客户端是否自动继承 WebView 的系统代理/PAC？更新/API/外部集成是否需要遵循系统代理？
8. 证书校验在测试期是否可能被关闭？有没有发布门禁阻止调试开关进生产（→《本地敏感数据与密钥管理方案》）？
9. 生产日志落盘位置、级别、脱敏规则是什么（→《日志与可诊断性技术方案》）？前端日志是否显式接线到后端？
10. 生产构建是否含调试符号、源码映射、示例配置、测试密钥？构建产物清单由谁核对？
11. 这些基线分别由哪道 CI 门证明？门红了是否阻断打标签/发布（→《CI矩阵与质量门禁方案》）？
12. 开发态、server 模式、dev 构建、打包安装四种形态，是否走同一套实现？在 dev 下验过的结论凭什么推广到发布包（→《托盘技术方案》「开发态与安装态是否等价」）？

交付给 AI 的设计结果应包含：生产基线清单（逐项含配置项、期望值、证据）、构建 tag 矩阵、CSP 策略、代理策略、形态等价性验证、CI 门位置。

## 核心纪律

### 一、基线清单：逐项「期望值 + 证据」

| 基线项 | 生产期望 | 可观察证据 |
|---|---|---|
| DevTools / Inspector | 显式禁用（配置值为真，不是默认） | 生产配置片段 + 发布门禁断言 |
| CSP | 显式注入，最小权限起步 | 目标 WebView 中生效记录（响应头/策略报告） |
| Agent / MCP tag | 生产不带该 tag | 构建命令清单 + 产物能力探测 |
| 证书校验 | 不可关闭 | 生产构建静态检查 + 自签证书被拒冒烟 |
| 调试符号/源码映射 | 按决策剥离或保留，但写入产物清单 | 产物清单 + 符号文件归档（→《签名打包与更新分发技术方案》） |
| 示例配置/测试密钥 | 不进产物 | 秘密扫描 + 产物内容清单 |
| 前端日志 | 显式接线到后端落盘 | 生产前端日志落盘验证（→《日志与可诊断性技术方案》） |
| 代理/PAC | 明确「遵循 / 不遵循」的书面决策 | 网络请求代理策略说明 |

**「代码里写了」不是证据**。每一项都要有能在产物或运行中观察到的判据（→《托盘技术方案》的五层验证纪律）。

### 二、CSP：白名单起步，逐项放宽要登记

- 起点至少包含：`default-src 'none'`、`script-src 'self'`、`frame-src 'none'`、`object-src 'none'`；需要样式/图片/字体/连接时逐项登记来源与理由。
- 禁止用 `unsafe-inline`/`unsafe-eval` 作为「先让它跑起来」的默认解法；确需使用要写明替代方案与触发移除条件。
- 注入位置固定在生产路径的一处中间件/构建步骤；dev 构建可以有不同策略，但**差异本身要成文**，不能靠环境变量偶然不同。
- 三平台 WebView 支持的指令不同（WebKitGTK / WebView2 / WKWebView），逐平台实测；未实测的标未验，不用一个平台结果替其他平台背书。
- CSP 报告/违规日志不含用户数据，且与错误码、关联 ID 对齐（→《日志与可诊断性技术方案》《状态码方案》）。

### 三、构建 tag 与能力面

| 构建形态 | 允许的额外能力 | 门禁 |
|---|---|---|
| dev | DevTools、热重载、MCP/Agent 驱动、mock 服务 | 仅本地 |
| server（E2E） | 脚本化驱动路径 | 独立 CI job（→《CI矩阵与质量门禁方案》） |
| 打包安装（生产） | 无 | tag 清单 + 产物能力探测 + 发布门禁 |

- **生产默认不带任何控制类 tag**；tag 列表写进构建脚本单一入口，不靠「谁记得不加」。
- 主大纲五档把「MCP 生产启用」列为暂缓：书面理由 + 触发条件必须保留；真要启用时，除 tag 外还要额外的认证层与网络暴露审查，不是打开开关就行。
- 构建 tag 与版本号、身份一样进产物清单（→《版本号方案》《产品身份单一源方案》）。

### 四、代理、证书与网络边界

- 框架宿主 Go HTTP 客户端**通常不自动继承 WebView 的系统代理/PAC**（具体行为按锁定版本核实，标待验证）。更新、API、外部集成要显式决策：手动 Transport / 显式代理层 / 明确不遵循。
- 决策要写成「哪些请求走哪条路」，不是一句「跟随系统」；企业网络、离线、代理认证失败各有降级（→《网络与离线弹性技术方案》）。
- 证书校验不可关；企业自定义 CA、证书固定、mTLS 的取舍见《本地敏感数据与密钥管理方案》。
- 自定义协议/外部链接的 scheme 白名单属于同一条信任边界（→《外部链接与协议回调安全方案》）。

### 五、形态等价性

浏览器预览、server 模式、dev 构建、打包安装四种形态里，托盘协议、窗口后端、CSP 注入、日志接线、几何读写可能不是同一套实现。**在 dev 下验过的结论，必须在打包安装形态下重跑一遍**（→《托盘技术方案》《窗口与多窗口技术方案》）。发布门禁里固定一条「安装态冒烟」，而不是靠开发者自觉。

## 常见根因表

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 发布包能打开 DevTools | 依赖默认值，未显式禁用 | 显式配置 + 发布门禁断言 |
| 生产没有 CSP | 只在 dev 中间件里注入过 | 生产路径单一注入点 + WebView 实测 |
| 生产仍可被 Agent 控制 | 构建脚本带了控制 tag | tag 清单单源 + 产物能力探测 |
| dev 正常、安装包异常 | 四种形态实现不同，未重跑 | 安装态冒烟进发布门 |
| 企业内网更新失败 | Go 侧未继承代理，无显式策略 | 显式 Transport 或书面「不遵循」决策 |
| 测试期关掉的证书校验漏进生产 | 调试开关无门禁 | 静态检查 + 自签证书被拒冒烟 |
| 发布说明写「已关闭」但没证据 | 只改了配置没验产物 | 基线清单逐项附可观察证据 |

## 先设计测试矩阵，再开始实现

| 维度 | 要覆盖 |
|---|---|
| 配置 | 每项基线的期望值、实际产物值、差异断言 |
| CSP | 合法资源加载、违规被阻、三平台 WebView、报告不含用户数据 |
| tag | dev / server / 生产三种构建的能力探测 |
| 网络 | 自签证书被拒、企业 CA、代理开/关/认证失败、离线 |
| 形态 | dev / server / dev 构建 / 打包安装，逐项重跑 |
| 门禁 | 故意带一次调试开关，确认发布门真的红 |
| 未验 | 未实测平台与指令明确列出 |

## 给 AI 的实施约束模板

> 先给出生产基线清单（逐项含配置项、期望值、可观察证据）、构建 tag 矩阵、CSP 策略与注入位置、代理/证书策略、形态等价性验证步骤，再写构建脚本。**生产 DevTools 必须显式禁用而不是依赖默认值；CSP 必须显式注入并在目标 WebView 实测；生产构建不带任何控制/Agent tag；证书校验不可关闭；构建 tag 与产物清单由单一入口管理。** 任何行为以锁定框架版本源码为准，查不到证据的写「待验证」；「代码里写了」不算验收证据。实现后为每项基线补可观察断言与发布门禁，故意带一次调试开关验证门真的红，并列出未实测平台。所有策略、tag 名、CSP 指令由当前项目需求与平台实测决定。

## 五档定位

| 档位 | 本方案承担 |
|---|---|
| 一档 | DevTools/MCP/CSP 的决策与「显式而非默认」原则 |
| 二档 | 完整基线清单、tag 矩阵、代理策略、证书校验门 |
| 三档 | 前端日志接线、形态等价性冒烟、CSP 违规观测 |
| 四档 | 基线断言进发布门禁、产物清单核对、安装态冒烟 |
| 五档 | MCP 生产启用按主大纲暂缓（保留理由与触发条件）；证书固定按风险分档 |
