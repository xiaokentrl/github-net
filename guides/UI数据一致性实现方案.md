# UI 数据一致性实现：Wails3 + Go 专用方案

## 定位与硬性目标

《统一同步层技术方案》是纪律母法（事实/镜像/意图、推/拉/兜底、失效从宽、乐观对账）；本方案是它的 **Wails3 + Go 实现层**——回答：信号协议怎么定、Go 落定枢纽怎么写、前端订阅中心怎么接、类型安全怎么保证。母法定「什么必须成立」，本方案给「代码长什么样」；实现与母法冲突时以母法裁决。

**硬性目标**：任何命令的「落定 → 失效 → 重取 → 收敛」全部复用同一套设施——业务代码只声明**「我改了哪个领域的哪些实体」**（一行），其余（发信号、兜底、节流、前端失效、重取、单飞）由基础设施完成。出现第二处手工刷新，即架构破坏。

包落位：Go 侧 `internal/sync/`、前端侧 `src/sync/`（→《后端目录结构方案》《前端目录结构方案》）。术语约定：母法所称「统一落定同步层」，实现后称**落定枢纽（hub）**——同一事物，各方案以任一名称指代。

## 信号协议（Go ↔ 前端的合同）

- **通道约定**：每领域一个事件通道 `sync:{domain}`（如 `sync:library`）；载荷**只带标识与版本，不带数据**：

```json
{ "domain": "library", "ids": ["book:42"], "version": 183 }
```

- **版本号**：权威层为每领域维护单调递增计数器，`Settle` 时递增并随信号发出——前端用它做**乱序拒绝**（旧版本信号丢弃，母法纪律）。
- **双端单源 + parity 门**：事件名与领域标识在 Go 定义为常量，生成或镜像到 TS（生成方式随锁定版本**待验证**；无生成则手维护 + parity 测试门）。拼错事件名在构建期暴露，而不是运行期静默不触发——这是母法第 7 问的落地。
- **领域清单与后端 `domains/` 一一对应**：新增领域 = 新增目录 + 注册信号通道 + 登记 store 投影，三处一起动。

## Go 侧：落定枢纽 `internal/sync/`

```go
type Hub interface {
    // Settle 落定即刻生效：递增领域版本 → 节流合并 → 发出 sync:{domain} 信号
    Settle(domain string, ids ...EntityID)
    // OnSettle 注册领域级失效回调（级联领域、缓存失效 → 《缓存一致性方案》）
    OnSettle(domain string, fn func(ids []EntityID, version uint64))
}

// 业务侧唯一用法（全库只能长这样）：
// func (s *LibraryService) Rename(ctx context.Context, id ID, name string) error {
//     if err := s.store.Rename(id, name); err != nil { return err }
//     s.hub.Settle("library", id)   // ← 命令声明的全部同步责任就是这一行
//     return nil
// }
```

- **落定三步内置**：`Settle` 即刻发信号（推）；前端收到后重取（拉）；hub 内置**延迟兜底**——短间隔后重发同领域信号，覆盖丢失/乱序/晚到（间隔写进配置，即母法的「陈旧窗口上限」声明）。
- **节流合并**：同领域高频 `Settle`（批处理逐条落定）在 hub 内合并为一次信号——防事件风暴（母法「高频变更」条目的实现位）。
- **服务生命周期**：hub 挂 `ServiceStartup/ServiceShutdown`，兜底 timer 可取消，不依赖进程退出自然终止。
- **幂等**：重复 `Settle` 同实体安全（版本继续单调），落定刷一次、兜底刷一次、焦点再刷一次互不干扰。

## 前端侧：订阅中心 `src/sync/`

- **唯一订阅点**：`sync:{domain}` 信号的监听只存在于订阅中心；组件与 store 不得自行 `EventsOn`（grep 审查零例外——母法「唯一入口」的前端侧）。
- **失效 → 重取**：收到信号 → 版本比对（旧则丢）→ 触发对应 store 重取；**同 key 在途重取单飞合并**（多窗口/兜底/焦点同时触发只打一次权威，→《缓存一致性方案》）。
- **兜底轮询**：每领域低频兜底间隔 + **焦点恢复与系统唤醒重查**（应用事件随锁定版本**待验证**）——信号丢失时的最后保险（母法三通路）。
- **订阅生命周期**：订阅经 hooks 与组件/窗口成对清理（→ 前端结构方案 hooks 纪律）。
- **落定的前端触发**：前端命令包装（`api/` 层）在调用成功后自动走同一 `settle` 语义——前端同样不手工刷 store。

## 乐观更新 helper（固定形状的实现位）

母法定形状（取消在途 → 快照 → 写入 → 落定对账），本方案给实现：`api/` 层提供统一的乐观动作 helper——

- 自动取消同 key 在途重取与在途乐观动作；
- 快照写入 store 镜像并标记「乐观占位」（界面可区分）；
- 落定（成功或失败）统一从事实源对账：成功等 `Settle` 失效收敛，失败默认重取真实状态；
- **不提供「成功转正」API**——结构上杜绝第二条事实源。

## 非 UI 冒烟的实现路径

母法要求「不经 UI 修改事实、观察所有表面收敛」：`cmd/cli/` 直接调领域服务 → `hub.Settle` 照常触发 → 前端各投影在兜底窗口内收敛。**CLI 能触发完整同步链，是 hub 架构级成立的证明**（→ 后端结构方案 CLI 一节）。

## 验收清单

- [ ] 事件名/领域标识 parity 门进 CI，拼错构建期报错
- [ ] 落定即刻刷新 + 兜底二次刷新实测（断开信号路径，兜底仍收敛）
- [ ] 乱序拒绝：旧版本信号不覆盖新数据
- [ ] 节流：批量 1000 条落定只产生一次前端刷新
- [ ] 单飞：并发 100 次同 key 重取，权威命中 1 次
- [ ] 乐观对账：成功收敛、失败重取、无「转正」路径（代码审查 + 测试）
- [ ] 全库 grep：组件与 store 零直接事件监听、零手工刷新
- [ ] 非 UI 冒烟：CLI 改事实 → 各表面在声明的兜底窗口内收敛

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 信号发了界面没动 | 事件名拼写错误、无 parity 门 | 常量单源 + 构建期报错 |
| 界面显示被旧数据覆盖 | 乱序信号未拒收 | 版本单调 + 比对丢弃 |
| 信号丢了永远陈旧 | 无兜底或兜底不可取消 | hub 内置兜底 + 间隔声明 |
| 批量时界面抽搐 | 逐条 Settle 未合并 | hub 节流 |
| 刷新打爆权威层 | 无单飞 | 同 key 在途合并 |
| 某处界面自己刷了 | 旁路刷新路径 | grep 审查 + helper 收口 |
| 乐观值转正成事实 | 成功路径手写结果 | helper 不提供转正 API |
| CLI 改了数据界面全不知 | hub 只在 UI 路径生效 | 领域服务内落定，与入口无关 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 先给出信号协议（通道命名、载荷字段、版本单调）与领域↔通道清单。Go 侧 `internal/sync/` 实现落定枢纽：Settle 即刻 + 延迟兜底 + 节流合并 + 幂等，挂服务生命周期；业务代码的同步责任只有一行 `Settle` 声明。前端 `src/sync/` 是唯一订阅点：版本比对拒乱序、重取单飞、兜底轮询与焦点/唤醒重查、订阅成对清理。事件名与领域标识双端单源 + parity 门进 CI。乐观更新只经统一 helper（取消在途 → 快照 → 占位 → 落定对账），无转正 API。全库不得出现第二处事件监听或手工刷新。实现后跑验收清单，补乱序、节流、单飞与乐观对账的回归测试，并完成一次 CLI 非 UI 冒烟。

方案确认后再改代码；事件系统与生成能力随锁定的框架版本核实，与本方案冲突时先报告差异再裁决。
