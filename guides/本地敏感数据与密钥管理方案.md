# 本地敏感数据与密钥管理方案：通用规划方案

## 这份方案是做什么的

来源：OWASP Desktop App Security Top 10 的 DA3（敏感数据暴露）、DA4（密码学误用）、DA7（不安全通信）、DA9（含已知漏洞组件），以及桌面应用安全落地实践中反复出现的三条结论——**桌面运行在不受信环境、用户完全控制 OS/二进制/内存**；**凭据必须交给平台安全存储**；**静态加密的难点从来不是算法而是密钥管理**。

母法方案：《安全边界与权限技术方案》（信任边界与暴露面）、《应用状态与持久化技术方案》（落盘与备份）、《网络与离线弹性技术方案》（代理与重试）、《日志与可诊断性技术方案》（脱敏与诊断包）、《默认安装目录规划方案》（目录与权限）、《登录与权限方案》（服务端强制校验）。

本方案只回答一件事：**敏感数据与密钥在这台用户可控的机器上，住在哪里、怎么加密、怎么轮换、怎么不漏进日志**。不管认证/授权模型（→《登录与权限方案》）、不管输入校验（→《输入数据验证方案》）、不管构建期签名密钥的 CI 保管（→《签名打包与更新分发技术方案》）、不管遥测的同意与合规（主大纲五档已列为暂缓项，触发条件见主大纲）。

先说清边界：**客户端加密不是「防用户」**。用户拥有设备与进程，任何硬编码在二进制里的密钥都能被 `strings` 搜出来。它的目标是提高设备丢失、恶意软件读盘、日志外泄时的成本，并把「必须保密的东西」压缩到最小集合。

不预设：产品是否处理 PII、是否联网、是否有账号、加密算法套件、平台最低版本。未核实的标**待验证**。

## 开始写代码前，先让 AI 回答这些问题

1. 数据分类清单是什么（公开 / 内部 / 敏感 / 极高）？每类的例子、允许的存放位置、允许的传输路径？
2. 哪些值属于「凭据」：token、刷新令牌、API key、用户口令、设备私钥、加密密钥？各自生命周期与轮换触发条件？
3. 三个目标平台的系统凭据存储分别是什么（Windows DPAPI / macOS Keychain / Linux Secret Service 或 libsecret）？在目标版本上可用性如何？**没有 keyring 的会话（容器、CI、精简桌面）怎么降级？**
4. 静态数据是否需要加密？是整库加密、文件级加密还是字段级？密钥从哪来（用户口令派生 / 平台存储 / 服务端下发）？
5. 密钥与密文是否可能落在同一目录、同一备份包、同一诊断包里？备份/恢复/迁移时密钥怎么处理？
6. 二进制里是否存在硬编码密钥、测试用 token、示例域名？CI 有没有秘密扫描？
7. 网络请求是否强制 TLS 并校验证书？企业自定义 CA、证书固定、mTLS 分别是什么决策？测试时关闭校验的开关是否可能漏进生产？
8. Go 侧 HTTP 客户端是否遵循系统代理/PAC？框架宿主客户端不自动继承时的显式策略是什么（→《网络与离线弹性技术方案》）？
9. 日志、崩溃快照、诊断包、支持导出在**写入前**（不是上传后）过滤哪些字段？白名单还是黑名单？
10. 权限：数据目录 `0700`、敏感文件 `0600` 由谁设置？WebView 用户数据目录是否显式设为应用私有？
11. 用户登出、切换账号、卸载、删除数据时，内存与磁盘上的凭据各怎么清理？清理失败如何可见？
12. 目标市场的合规要求（GDPR/CCPA 等）是否要求数据可携带、可删除、留存有上限？删除请求要覆盖哪些副本（备份、缓存、日志、支持导出）？

交付给 AI 的设计结果应包含：数据分类表、凭据存放矩阵、加密与密钥生命周期图、TLS/证书策略、脱敏白名单、目录权限、删除与轮换流程、失败策略与测试矩阵。未经用户确认，不要擅自决定「是否采集用户数据」这类改变产品性质的行为。

## 核心纪律

### 一、先分类，再谈加密

| 分类 | 例子 | 允许的存放 | 硬要求 |
|---|---|---|---|
| 公开 | 图标、静态文案、公共配置 | 任意 | 无 |
| 内部 | 窗口几何、UI 偏好、非敏感缓存 | 应用数据/缓存目录（→《默认安装目录规划方案》） | 与敏感数据分目录，便于整体清理 |
| 敏感 | token、PII、业务数据、用户文档内容 | 受限目录；凭据进平台安全存储 | 落盘加密或字段级加密；不进日志 |
| 极高 | 私钥、主密钥、签名凭据 | 平台安全存储 / 外部 HSM；**不进应用数据目录** | 二进制零硬编码；轮换有演练记录 |

分类表是后续所有决策的单一源。没有分类表就选加密算法，等于把「哪些数据值得保护」留给了写代码时的直觉。

### 二、凭据交给平台，不自己造轮子

| 平台 | 首选 | 不可用时的降级 |
|---|---|---|
| Windows | DPAPI（绑定用户登录会话） | 明确失败并提示，或按产品决策改为「每次启动重新认证」；**不静默写明文** |
| macOS | Keychain（含访问组与 ACL） | 同上；注意签名与 Bundle ID 是 Keychain 访问的前置条件 |
| Linux | Secret Service / libsecret（会话总线） | 无 keyring 会话显式报「不可用」；CI/容器路径与生产路径分开，不复用同一分支 |

四条判据：

- **明文凭据文件永远不是降级方案**。降级要么让用户重新认证，要么明确禁用依赖凭据的功能，并给出用户能理解的解释（→《操作反馈方案》）。
- **不要把密钥和密文放一起**。文件加密后把解密密钥写在同目录，等于没有加密；DPAPI/Keychain 的价值正是把密钥管理交给已认证的会话。
- **结构化数据要单独决策**：本地 SQLite 是否用整库加密（如 SQLCipher 一类方案）还是字段级加密，取决于查询需求、性能预算与备份策略（→《应用状态与持久化技术方案》）。选型必须写明「密钥从哪来、丢了会怎样」。
- **内存清理要诚实**：Go 的字符串不可变、GC 会复制，无法保证敏感值及时擦除。方案里写「尽量缩短持有时间、避免放进日志与错误、避免随诊断包序列化」，不要写「已从内存清除」这种无法验收的结论。

### 三、密码学使用纪律

- 只用标准库/成熟库的标准原语（如 AES-GCM 一类 AEAD），禁止自研算法与自造协议；nonce/IV 随机且不可重用，KDF 参数显式登记。
- 每个加密域有版本标记与算法标识，为轮换留出路径；轮换流程要有「旧密钥读、新密钥写、完成后旧密钥销毁」的可观察步骤与演练记录。
- 完整性校验与加密同等重要：只加密不校验，密文被篡改后可能解出「看起来合法」的垃圾值（→《应用状态与持久化技术方案》的损坏降级纪律）。
- 密钥、token、口令、文件内容不得出现在日志、错误码、崩溃快照、支持导出里（→《日志与可诊断性技术方案》）；脱敏在**写入前**做，后处理只是第二道防线。
- 二进制秘密扫描进 CI；文档与配置示例里的值只能是占位符（→《配置文件方案》）。

### 四、传输与信任边界

| 决策 | 要写清 | 验收证据 |
|---|---|---|
| TLS | 最低版本、证书校验不可关闭、测试开关不得进生产 | 生产构建中无跳过校验分支的静态检查 |
| 自定义 CA / 企业环境 | 是否信任系统 store、是否允许用户导入 CA | 目标企业网络下的实测记录 |
| 证书固定 | 是否固定、固定什么（公钥/证书哈希）、轮换与失效预案 | 固定值登记表 + 轮换演练（**固定会引入运维成本，不是默认选是**） |
| mTLS | 是否双向、客户端证书放哪 | 与平台安全存储的衔接说明 |
| 代理/PAC | Go 宿主 HTTP 客户端不自动继承系统代理，是否显式构造 Transport | 代理策略说明（→《网络与离线弹性技术方案》） |
| 服务端强制 | 客户端状态一律不可信；权限、配额、关键算法在服务端校验 | 服务端校验点清单（→《登录与权限方案》） |

**不受信客户端**是桌面安全的出发点：本地配置里一个布尔值改成 `admin=true` 不能提权，UI 隐藏按钮不能当鉴权，序列化外部数据时用受控格式（JSON），不反序列化任意类型。

### 五、删除、轮换与卸载

- 每条敏感数据都有留存上限与删除触发（用户删除请求、登出、卸载、试用期结束）；按**存储位置**分配策略，而不是笼统按「数据类型」（本地库、日志、缓存、备份、支持导出、崩溃上报各有各的 owner）。
- 删除要覆盖副本：备份快照、临时导出、缓存文件、诊断包。仅删生产库不算删干净（→《磁盘资源缓存管理方案》《应用状态与持久化技术方案》）。
- 自动化就是策略：靠人记得删共享盘里的导出包，一定会漏。定时任务/生命周期策略 + 例外标记（关联活跃工单才延长）才是可验收的实现。
- 卸载与换机：明确「哪些数据随卸载删除、哪些保留、用户如何先导出」（→《默认安装目录规划方案》）。数据可携带性与删除权在受监管市场是硬要求。

## 常见根因表

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 二进制被 `strings` 搜出密钥 | 硬编码 AES key / 测试 token 进了生产 | 极高类不进应用目录 + CI 秘密扫描 + 示例占位符 |
| 加密了却仍能直接读数据 | 密钥与密文同目录、或 KDF 参数可推导 | 密钥交给平台安全存储；轮换演练 |
| 无 keyring 会话里凭据变成明文 | 降级路径静默写文件 | 降级三档：明确失败 / 重新认证 / 禁用功能，且用户可见 |
| token 出现在日志或诊断包 | 脱敏放在上传后处理，或黑名单漏字段 | 字段白名单 + 写入前过滤 + 诊断包内容清单 |
| 测试环境关掉的证书校验漏进生产 | 调试开关没有发布门禁 | 生产构建静态检查 + 发布门禁（→《CI矩阵与质量门禁方案》） |
| 删除请求只删了主库 | 没按存储位置登记副本 | 留存/删除矩阵 + 自动化清理 + 副本清单 |
| 本地改配置就提权 | 把客户端状态当授权依据 | 服务端强制校验 + 信任边界图 |
| 企业内网请求直连失败 | Go 宿主不继承系统代理/PAC | 显式 Transport 或明确「不遵循」的书面决策 |

## 先设计测试矩阵，再开始实现

| 维度 | 要覆盖 |
|---|---|
| 平台存储 | 三平台 keyring 可用/不可用/被拒绝/用户解锁四种状态；降级路径可观察 |
| 加密 | 加解密回环、篡改密文被拒、nonce 不重用、轮换读写并存、密钥丢失的明确失败 |
| 秘密泄漏 | CI 扫二进制、扫日志、扫崩溃快照、扫诊断包，断言不含白名单外字段 |
| 传输 | 过期/自签证书被拒、企业 CA、固定值轮换、代理/PAC 下的请求路径 |
| 权限 | 数据目录 `0700`、敏感文件 `0600`、WebView 用户数据目录私有 |
| 生命周期 | 登出、切换账号、卸载、删除请求、备份恢复后凭据仍可用或明确需重新认证 |
| 形态 | dev / server / 打包安装 / 无 keyring 容器，分别跑一遍 |
| 未验 | 未实测的平台与合规项明确列出，不拿一个平台的结果替其他平台背书 |

## 给 AI 的实施约束模板

> 先给出数据分类表、凭据存放矩阵（三平台 + 降级）、加密与密钥生命周期图、TLS/证书/代理策略、脱敏字段白名单、目录权限与删除/轮换流程，再开始写代码。**凭据一律交给平台安全存储，禁止明文文件作为降级；密钥不得与密文同目录或同备份包；禁止硬编码密钥与自研密码学；测试期关闭证书校验的开关不得进入生产构建；脱敏必须在写入日志/诊断包之前完成；客户端状态不作为授权依据，权限与关键校验在服务端强制。** 任何「内存已清除」「已加密所以安全」这类不可验收的结论不得写入方案与发布说明，只能写可观察判据（扫描无命中、篡改被拒、轮换演练记录）。实现后补自动化门：秘密扫描、脱敏断言、证书校验、密钥轮换回环、无 keyring 降级。所有算法、平台最低版本、留存期限由当前项目需求决定，查不到证据的写「待验证」。

## 五档定位

| 档位 | 本方案承担 |
|---|---|
| 一档 | 数据分类表、凭据存放决策、信任边界与「客户端不可信」声明（不回答不写业务代码） |
| 二档 | 平台存储与降级、静态加密与密钥来源、TLS/代理策略、目录权限、脱敏白名单——第一个可分发里程碑前锁定 |
| 三档 | 轮换演练、诊断包与崩溃快照的脱敏覆盖、登出/切换账号清理 |
| 四档 | CI 秘密扫描、生产构建证书校验门、留存与删除自动化、受监管市场的删除请求响应路径 |
| 五档 | 证书固定、mTLS、HSM 可按产品风险分档暂缓；每笔暂缓写理由 + 触发重新评估的条件 |
