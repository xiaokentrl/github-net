# 托盘唤回不保窗口位置：一次「修了两次都没生效」的实证复盘

## 这份复盘是什么

配套《托盘技术方案》的**实证案例**：把一次真实项目里「左键单击／左键双击／右键单击／右键双击从托盘召回，主窗口都不保持关闭前位置」的历史修复记录、框架源码证据、失效链条和验收方案完整留档。

它证明的不是「某个 API 该怎么写」，而是通用方案里那条纪律为什么必须存在：**代码看着改对了、提交信息和发布说明都写了「已修复」，实际一次都没生效**。所有结论都绑定具体的框架版本、平台、会话与提交哈希；换版本、换桌面、换协议宿主必须重新核实，不能照抄。

复盘只做只读分析，**没有改动任何产品代码**。

## 二、四类手势的真实映射（Wails v3.0.0 / Linux StatusNotifier）

框架源码位置：`$GOPATH/pkg/mod/github.com/wailsapp/wails/v3@v3.0.0/pkg/application/`。

| 用户手势 | 协议／原生事件 | 框架回调 | 项目注册情况 | 结果 |
|---|---|---|---|---|
| 左键单击 | `Activate(x,y)` | `clickHandler` ← `OnClick`（赋值） | **注册两次**（`main.go:238` 与 `:281`） | 最终生效 `:281`：`IsVisible()` 为真就 `Hide()`——正是修复要删的调用 |
| 左键双击 | 宿主发两次 `Activate` | `doubleClickHandler` ← `OnDoubleClick`，Linux 实现**无调用点** | `:241` 注册 | 空转；两次单击各自执行覆盖后的逻辑，先隐藏再唤回，位置已丢 |
| 右键单击 | `ContextMenu(x,y)` 只记坐标、返回 `nil`；菜单由宿主用 DBusMenu 自绘 | `rightClickHandler` 挂在 `SecondaryActivate` 上，默认 `ShowMenu` | 未注册 | 弹菜单；「从菜单项显示主窗口」走 `requestWindowFocus()`，但位置恢复链本身已断 |
| 右键双击 | 无独立事件 | `rightDoubleClickHandler` 无 Linux 调用点 | 未注册 | 明确不支持，界面上却无任何说明 |
| 中键 | `SecondaryActivate(x,y)`（协议「次要激活」≠ 右键） | `rightClickHandler` | 未注册 | 触发框架默认菜单 |
| 滚轮 | `Scroll(...)` | 实现为空 | 未注册 | 无行为 |

关键证据：

- `systemtray.go:325` `OnClick` 是 `s.clickHandler = handler`，**赋值覆盖，不是追加**。
- `systemtray_linux.go:824` `Activate` → `clickHandler`；`:834` `ContextMenu` 空实现；`:844` `SecondaryActivate` → `rightClickHandler`；`:840` `Scroll` 空实现。
- 全文件搜 `doubleClickHandler` 只有字段声明与 `OnDoubleClick` setter，**Linux 没有分发双击**。
- `systemtray.go:157` `applySmartDefaults()`：未注册时自动挂 `ToggleWindow`；后者（`:170`）在显示分支调 `PositionWindow()` 按托盘位置摆窗、隐藏分支调 `Hide()`。默认行为本身就与「原位唤回」冲突。
- `systemtray_linux.go` 的 `Event` 里 `opened` 分支注释明确：菜单由宿主弹出，应用侧的「次要按钮」不是右键。

## 三、四条独立失效链（任一足够让位置丢失）

1. **回调覆盖**：修复新增 `OnClick(幂等唤回)`，却没删早期骨架的 `OnClick(可见则 Hide)`。赋值语义下后者赢。左键单击仍在销毁窗口映射。
2. **手势无回调**：`OnDoubleClick`／`OnRightDoubleClick` 在 Linux 从未被调用。发布说明里「所有召回路径」实际只覆盖了「左键单击 + 菜单项」两条，且这两条是坏的。
3. **时序空操作 + 框架二次摆位**：`WebviewWindow.SetPosition()` 在 `impl == nil` 时直接 `return`（`webview_window.go:1099`），而项目在 `NewWithOptions` 之后、`Run()` 之前调用它。框架 `linux_cgo.go:1357 move` 走 X11 `XTranslateCoordinates`，`window_get_position_x11` 在非 X11 display 或 native/surface 为空时返回 `0,0`。同时 `webview_window_linux.go:418`、`:464` 在建窗与 `show()` 后各调一次 `applyScreenPlacement()`，`InitialPosition` 零值即居中语义。相比之下 `Maximise/Minimise` 在 `impl == nil` 时会写进 `options.StartState` **有兜底**——所以「尺寸和最大化恢复了、位置没恢复」是同一族 API 两条不同路径的必然结果。正确形态是把位置写进 `WebviewWindowOptions` 的 `X/Y/InitialPosition`（`:163-175`）。
4. **落盘坏值 + 零值哨兵**：五个写入点全部直接序列化 `Size()/Position()`，无有效性门；`OnShutdown` 清理里那次「再存一次」在窗口销毁／未映射后读到零值并覆盖好值。本机 `window.json` 实测为 `{"X":0,"Y":0,"Width":0,"Height":0,"Maximised":false}`。读取侧兜底把 `X/Y` 归零，而恢复条件是 `if geo.X != 0 || geo.Y != 0`，于是 `SetPosition` 永不执行。另外 `0,0` 兼职「未记录」哨兵，用户真把窗口放原点也无法表达。

补充环境因素：`XDG_SESSION_TYPE=wayland`、`WAYLAND_DISPLAY=wayland-0`、`DISPLAY=:0`，应用自身在未显式设置时设 `GDK_BACKEND=x11`。强制兼容后端是有代价的产品决策（分数缩放发虚、输入法／无障碍差异），方案里必须记录用户确认与已知代价，且**不应覆盖用户显式设置**。

## 四、为什么「一直没有保持」

四类手势看似四个问题，其实是同一条链断在四处：**触发层**（旧 `OnClick` 覆盖 + 双击无回调）→ **收起层**（`Hide()` 销毁窗口映射）→ **恢复层**（`SetPosition` 空操作 + 框架二次摆位）→ **落盘层**（全零坏值 + 零值哨兵）。每一次修复只换了其中一环，且没有验证最终行为，所以用户看到的现象始终不变。

`main_test.go` 只测了托盘提示文案（`trayTooltipText`），**没有任何一条测试覆盖窗口状态机、注册唯一性或几何有效性**。这是「修复反复无效」能持续两版的直接原因。

## 五、建议的修复顺序（方案，不含实施）

1. **先建静态门**：扫描托盘回调注册点，同一入口出现两处即失败。删掉旧 `OnClick`，一个入口只留一个主人；把未注册入口的框架默认行为列进清单并显式定义。
2. **统一唤回状态机**：抽成可测的纯决策，读真实窗口状态后只做必要动作；已显示时只置前，绝不 `Hide()`、绝不重复 present、绝不按托盘位置定位。所有入口（单击、菜单项、单实例二次启动、Dock 重开、通知）共用它。四类手势中无回调的两个**明确标注不支持**，不写进发布说明。
3. **收起路径统一**：所有收起入口走同一种（按目标合成器实测选隐藏或最小化），关闭钩子、托盘菜单、标题栏按钮不得各走一种。
4. **几何读写分治**：位置写进**初始选项**并核对坐标口径（绝对 vs 显示器工作区相对、DIP vs 像素）；写入侧加有效性门，坏值不写盘、不覆盖好值；单一写入者；`hasPosition` 独立字段代替零值哨兵；写失败留可诊断记录（→《日志与可诊断性技术方案》《应用状态与持久化技术方案》）。
5. **后端决策归档**：把「是否强制 XWayland」作为产品决策记录，写明代价、用户确认、以及不覆盖用户显式设置的边界。
6. **补三道自动化门**：注册唯一性、几何有效性、唤回状态机幂等（见《托盘技术方案》「修复之后」）。
7. **实机验收**：按四类手势 × 四种窗口状态 × 连续激活的矩阵，在非默认位置上做前后几何快照；在**打包安装形态**下重跑，确认跑的是新进程。没有行为层记录前，提交信息与发布说明只能写「已调整 X，待实测」。

```sh

# 2. 框架注册语义与平台分发
grep -n -A3 'func (s \*SystemTray) OnClick' $GOPATH/pkg/mod/github.com/wailsapp/wails/v3@VERSION/pkg/application/systemtray.go
grep -n 'doubleClickHandler\|rightDoubleClickHandler\|Activate\|ContextMenu\|SecondaryActivate' $GOPATH/.../systemtray_linux.go

# 3. 位置类调用的提前返回与初始选项
grep -n -A6 'func (w \*WebviewWindow) SetPosition' $GOPATH/.../webview_window.go
grep -n -A8 'Initial Position' $GOPATH/.../webview_window_options.go
grep -n 'applyScreenPlacement()' $GOPATH/.../webview_window_linux.go

# 4. 落盘文件的实际内容（不是代码里以为的内容）
cat "$XDG_CONFIG_HOME/应用目录/window.json"

# 5. 历史修复是否真的删掉了旧行为
git log --oneline -S 'window.Hide()' -- main.go
git log --oneline -S 'tray.OnClick' -- main.go
git show <修复提交> -- main.go
```
