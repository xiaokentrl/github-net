# 缓存一致性：Wails3 + Go 通用方案

## 这份方案是做什么的

《统一同步层技术方案》管的是「界面镜像」这一种缓存的一致性；本方案把同样的追问推广到**全部缓存**——Go 侧领域缓存、派生/聚合数据、前端各级 store、外部响应缓存、文件与图标缓存。回答：什么可以缓存、缓存到什么一致级别、失效由谁声明、怎么防雪崩、怎么定上限。

**病根一句话**：缓存不一致几乎从不来自某一个 bug，而来自一个结构——**缓存存在了，但它的一致性级别与数据的变化特征不匹配**（用 TTL 缓存用户一改就变的数据；用永久缓存可变内容；key 少了作用域）。本方案的目标是让每个缓存先登记级别再存在。

**与母法的关系**：界面镜像的失效纪律（失效从宽、兜底轮询、乐观不转正）→《统一同步层技术方案》，本方案引用不重复；内存上限与淘汰 →《性能与资源基线技术方案》；离线缓存呈现 →《网络与离线弹性技术方案》；更新包缓存校验 →《签名打包与更新分发技术方案》。

## 核心：一致性四级（每个缓存必须落级）

| 级别 | 保证 | 适用 | 失效方式 |
|---|---|---|---|
| **L0 直读** | 强一致——不缓存，每次读权威 | 事实本体、低频读 | 无缓存即无失效 |
| **L1 失效驱动** | 写后失效 + 重取，兜底轮询保险 | 界面镜像、派生列表、聚合值 | 写路径显式失效（事件/信号） |
| **L2 TTL 容忍** | 陈旧窗口 ≤ TTL，可接受过期 | 参考数据、配置快照、远端元数据 | 定时过期 + 变更信号提前失效 |
| **L3 内容寻址** | 永久正确——key 即内容指纹 | 图标、缩略图、不可变导出物 | 无需失效（key 变了就是新条目） |

读侧的「一次读从哪里读、承诺什么新鲜度」的判定 →《全局一致性读策略》（本方案的读侧延伸）。

**判定规则**：

> **这段数据由谁改变、多久变一次？** 用户操作会变 → L0/L1；外部缓慢变化 → L2；永不变（或变了就是新对象）→ L3。

分级纪律：

- **升一级都要代价声明**：把 L1 降成 L2（图省事加个 TTL）= 用户操作后界面可能陈旧到 TTL 结束；把 L2 升成 L1 = 失效布线成本。**级别与数据特征不匹配的缓存，登记表上必须过不了审**。
- **L3 是化解失效的银弹**：可变对象内容寻址化（key 带 hash/版本号），失效问题直接消失——能 L3 的优先 L3。落盘缓存的目录纪律、容量预算与清理 →《磁盘资源缓存管理方案》。
- 界面镜像默认 L1，其纪律全部沿用同步层方案（失效从宽、兜底、乐观不转正），本方案不重复。

## 缓存登记表（存在之前先登记）

每个缓存一行，立项与评审对着它查：

| 缓存 | 层 | 级别 | Key 方案 | 上限与淘汰 | 失效触发 | 读者 |
|---|---|---|---|---|---|---|
| 例：库封面缩略图 | Go | L3 | `thumb:{fileHash}:{size}` | 500 条 LRU | 无需 | 详情页 |
| 例：领域元数据 | Go | L2 | `meta:{domain}` | 10 条 | TTL 60s + 领域写信号 | 各列表 |
| 例：列表投影 | 前端 | L1 | 领域投影标识 | store 上限 | sync 信号 + 兜底 | 表格/徽标 |

登记表是缓存世界的「事实读取登记表」（→ 同步方案）——**没有登记的缓存不许存在**，与「没有登记的镜像不许存在」同一条宪法。

## Key 纪律（一致性 bug 之母）

- **key 必须包含全部输入**：作用域、实体 ID、参数、版本。少一个作用域 = 跨实体串数据（用户 A 的缓存被用户 B 读到——多实体场景的事故之王）。
- **key 变更 = 缓存结构变更**：key 方案写进登记表，改 key 走版本化（旧 key 一并清理），不许静默换 key。
- **禁止裸对象当 key**：指针、未序列化结构做 key 是隐性不命中与内存泄漏之源。

## 写路径与失效纪律

- **失效优先于更新**：写路径只声明「我改了什么」，由失效机制（信号）让缓存重取——**不在写路径里顺手更新缓存值**（cache+db 双写竞态的根源；同步层「失效从宽」同一条）。
- **缓存永不权威**：任何缓存值不作为写操作的依据；miss 一律回权威取（镜像不转正的同一条，全缓存适用）。
- **负缓存短 TTL**：「查无此人」也缓存（短 TTL），防不存在的 key 反复打穿权威层。

## 防雪崩：单飞（single-flight）

- **同 key 在途合并**：miss 时同 key 的并发请求合并为一次权威读取，其余等待结果——冷启动、批量刷新、多窗口同时重取的雪崩保险（与任务队列「Channel+Kind 在途去重」同一形状，→ 任务队列方案；前端实现 `lib/timing` 的 `useSingleFlight`，判定表 →《防抖与节流方案》）。
- 兜底轮询、休眠恢复、焦点重查的并发重取都要过单飞（→ 同步方案边界场景）。

## 上限与淘汰

- **每个缓存必须有上限**：条数或字节数 + 淘汰策略（LRU 起步）——「缓存无上限」是性能方案内存来源清单的点名嫌疑（→ 性能方案），登记表的上限列不许空。
- 进程内缓存用带淘汰的现成结构，不手写 LRU（除非有实测理由）。

## 跨层分界（Go ↔ 前端）

- **权威在 Go，缓存在两端**：Go 侧领域缓存失效由领域写触发；前端镜像失效由 sync 信号驱动——**前端永不自行判断「数据该不该过期」**（它没有判定依据），过期判定只住在 Go。
- 多窗口：事实在权威层唯一；各窗口镜像靠信号失效收敛（→ 同步方案多窗口纪律）。
- 重启预热：缓存默认**惰性**（首读加载，→ 性能方案启动路径「可惰性」标注）；预热必须有实测收益才做，不做无依据预热。

## 测试矩阵

| 维度 | 要覆盖的情况 |
|---|---|
| 级别匹配 | 每个登记项：写后读、TTL 边界、L3 内容变更生成新条目 |
| 失效 | 非 UI 路径修改事实 → 各级缓存在兜底窗口内收敛（→ 同步方案冒烟） |
| 雪崩 | 冷启动并发同 key 读、多窗口同时重取 → 单飞合并（计数权威读取次数） |
| 边界 | 缓存到上限 → 淘汰生效、内存不越线（→ 性能方案内存实测） |
| 负缓存 | 不存在 key 反复查询 → 权威命中次数受控 |
| 重启 | 惰性加载首读正确；预热项收益复测 |

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 改了数据界面还是旧值 | L1 的数据被做成 L2（TTL 兜底掩盖失效缺失） | 登记表级别审查 |
| 越用越卡内存暴涨 | 缓存无上限 | 上限列不许空 |
| 用户 A 看到用户 B 的数据 | key 缺作用域 | key 全输入纪律 |
| 冷启动瞬间权威层被打爆 | 无单飞 | 同 key 在途合并 |
| 偶发读到刚被删的记录 | 负缓存缺失 | 短 TTL 负缓存 |
| 双写后缓存与库不一致 | 写路径顺手更新缓存 | 只失效不更新 |
| 缓存里读出旧值当依据 | 缓存值参与写决策 | 缓存永不权威 |
| 换 key 后旧条目泄漏 | 静默换 key 不清理 | key 版本化 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 任何缓存先登记：级别（L0–L3）、key 方案、上限与淘汰、失效触发、读者，登记表外不建缓存。级别按数据变化特征判定，不匹配者降级重审；能内容寻址的做 L3。key 含全部输入（作用域/ID/参数/版本），裸对象禁做 key。写路径只失效不更新；缓存永不作为写依据；负缓存短 TTL。同 key 在途单飞合并；每个缓存有上限与淘汰；前端不自行判过期，过期判定只在 Go。惰性加载为默认。实现后补一致性冒烟（非 UI 路径修改 → 收敛）、单飞计数、上限与淘汰的测试，并明确列出未覆盖的组合。

方案确认后再改代码；引入新缓存库/框架前先过登记表评审，不擅自选型。

## 五档定位

- **一档**：一致性四级判定 + 缓存登记表初稿（哪些数据可缓存、落哪级；大纲准入条目在二档「缓存登记与一致性分级」）。
- **二档**：L1/L2 缓存实现、单飞、上限淘汰；登记表全覆盖。
- **三 / 四档**：负缓存、预热实测、跨窗口收敛全量验证。
