# 多语言实现：Wails3 + Go 专用方案（一语言一文件）

## 定位与硬性目标

这是《国际化与输入技术方案》在 Wails3 + Go 上的**实现配套方案**。通用纪律（键化、bidi、IME 组合态、语言切换联动、持久化只存规范化值）以该方案为准；本方案回答「具体怎么落地」。

**硬性目标：新增一种语言 = 新增一个 JSON 文件。** 不改任何代码、不做任何注册、不动任何配置——Go 侧和前端同时自动收录该语言。凡设计上做不到这一点的环节（手工注册语言清单、前端逐语言 import、代码里的语言分支），都是本方案要排除的结构。

覆盖三个消费端：Go 后端（托盘菜单、原生对话框、系统通知、用户可见错误信息）、WebView 前端（全部界面文案）、构建期校验（CI 门禁）。

## 核心设计：一份文件，两个消费端，零注册

```
locales/
├── zh-CN.json        # 基准语言：键集的权威（缺失键的回退源）
├── en-US.json
└── ja-JP.json        # 新增语言 = 只加这一个文件
```

两端都用**通配发现**，不存在任何逐语言登记点：

- **Go 侧**：`//go:embed locales/*.json`——新增文件编译期自动进入嵌入包。
- **前端侧**：Vite `import.meta.glob('/locales/*.json')`（非 eager）——新增文件自动进入按需懒加载清单。

文件位置的唯一约束：**必须同时在 Go 模块目录树内、且前端构建可访问**。推荐放仓库根 `locales/`，Go 从模块根 embed；Vite 通过 alias（`@locales`）+ `server.fs.allow` 引用。若前后端分包到互相不可见的位置，用构建期复制步骤（glob 复制同样零改动），但优先用 alias，少一道生成环节。

## 语言文件格式

- **JSON、扁平点分键**（`menu.file.open`、`errors.network.timeout`）：扁平结构让键集对比、占位符校验、CI 报告都是一层字符串操作，不需要递归合并逻辑。
- **占位符**：统一 ICU 形式 `{name}`；同键在各语言中的占位符集合必须一致（CI 校验）。
- **复数**：值内使用 ICU 复数语法 `{count, plural, one {…} other {…}}`。**复数规则不允许按语言写代码**——Go 侧用 go-i18n v2（内置 x/text 的 CLDR 复数规则，覆盖全部语言），前端用内建 `Intl.PluralRules`。这样任何语言的复数都开箱即用，新增语言文件时不需要动复数逻辑。
- **日期、数字、排序不进语言文件**：展示层一律走 `Intl.DateTimeFormat / NumberFormat / Collator`（→ 通用方案的「数据归数据、展示归展示」）；Go 侧生成的字符串（通知、错误）尽量避免内嵌日期时间，必须时用固定格式或把数值作为占位符传入。
- **缺键策略**：非基准语言允许缺键——运行时回退基准语言值并记一条警告日志。这让翻译可以增量进行，新语言文件不需要一次写满；但发布语言要求零缺键（见 CI 门禁）。

## Go 侧加载器

一个独立的小包 `i18n`，全局唯一入口：

- `//go:embed locales/*.json` 加载全部语言到内存（语言包体积小，全量加载即可；无需按需卸载）。
- 基于 go-i18n v2 的 `Localizer`，**回退链**：`zh-CN → zh → 基准语言`；无效语言标签直接落到基准。
- API：`T(lang, key, map[string]any) string`。键是普通字符串，不做编译期检查——拼写错误的键运行时回退为键名本身并记警告，CI 的键齐性检查兜底。
- **消费方**：托盘菜单模板、原生对话框、系统通知、按错误码翻译的用户可见错误信息（错误码本身稳定、进日志，文案从语言包出——与《日志与可诊断性技术方案》的错误码纪律衔接）。
- 语言参数从哪里来：用户设置（→《应用状态与持久化技术方案》，持久化存规范化 BCP 47 标签），首次启动取系统语言探测，之后只信设置。

## 前端侧

- Vite glob 懒加载：切换到某语言才动态 import 该文件，未用语言不进首屏 bundle。
- 一个响应式语言 store：`locale`（来自设置）+ `t(key, params)`；组件只经 store 取文案，不各自 import JSON。
- 切换即时生效、不刷新页面；同时更新 `document.documentElement.lang` 与 `dir`（RTL 语言翻转，→ 通用方案）。
- 与 Go 的语言一致性由设置单源保证：前端切换 = 写设置 = 广播给 Go（→ 同步层），Go 侧通知、菜单读同一设置值；不允许两层各存各的当前语言。

## 语言切换联动表

对应通用方案的联动表，本方案下各层的实现与生效方式：

| 层 | 机制 | 生效时机 |
|---|---|---|
| 前端全部文案 | 响应式 store | 即时 |
| 原生对话框 / 系统通知 | Go 侧 `T()`，每次调用取当前语言 | 下一次调用即新语言 |
| 托盘菜单 / 应用菜单 | Go 侧用新语言重建菜单 | 重建即时生效；运行时重建能力按锁定的框架版本**待验证**，不可重建则重启生效并写明降级 |
| 打包安装层（快捷方式描述、文件关联） | 打包期固化 | 随安装 / 更新，不随运行时切换 |

## 构建期校验（CI 门禁）

一个 Go 测试（读取同一份 `locales/*.json`，前后端共用）：

1. **基准语言完整**：基准文件自身键无空值、占位符合法、ICU 语法可解析。
2. **键集差异报告**：每个语言文件与基准的键集 diff（缺失 / 多余）——缺失允许但列清单；**标记为发布语言的目标必须零缺失**（清单随版本存档）。
3. **占位符一致**：同键占位符集合与基准不一致 → 阻塞（运行期会把 `{name}` 原样漏给用户）。
4. **ICU 可解析**：任何一侧解析失败的值 → 阻塞。
5. **多余键**：语言文件里出现基准没有的键 → 阻塞（通常是改名后旧语言没跟上，留着就是死文案）。

## 验收清单

| 项 | 验收 |
|---|---|
| 新增语言演练 | 复制基准文件 → 翻译 → CI 绿 → 全表面生效；全程不改代码，记录耗时作为回归基线 |
| 回退链 | 缺键、缺语言文件、无效语言标签，各自落到基准且记警告 |
| 切换 | 按联动表逐层核对：前端、托盘、通知、错误弹窗 |
| 复数 | 目标语言的数量场景（1 / 2 / 5 / 0）逐个验证 |
| RTL | 加入 RTL 语言文件时布局翻转、混排隔离（→ 通用方案） |
| 一致性 | 前端与 Go 的当前语言永远相同（切前端语言后立即触发一条通知验证） |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 语言包一律是 `locales/*.json` 扁平键 + ICU 占位符/复数；Go 侧 `//go:embed` + go-i18n v2（CLDR 复数），前端 Vite glob 懒加载 + 响应式 store——**任何新增语言文件不得要求代码改动或注册**，先证明这一点再写其余代码。基准语言键集为权威，缺键运行时回退基准并记警告；当前语言以设置为单源，前端与 Go 共享，不允许两处各存。错误信息按稳定错误码从语言包出文案；托盘/菜单切换按联动表实现，运行时重建菜单能力先按锁定版本验证，不可重建则写明重启生效的降级。日期数字用 Intl，不进语言文件；持久化只存 BCP 47 标签。实现后补键齐性、占位符一致性、ICU 解析的 CI 测试，并完成一次新增语言演练。

方案确认后再改代码；任何能力与锁定的框架版本不符（如菜单运行时重建），先报告差异并等待裁决。
