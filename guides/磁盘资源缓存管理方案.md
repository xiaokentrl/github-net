# 磁盘资源缓存管理：通用规划方案

## 这份方案是做什么的

《缓存一致性方案》定了缓存的一致性分级（L3 内容寻址是落盘缓存的主力）与内存上限；本方案管**落盘到磁盘的缓存**的工程面：目录放哪、容量怎么治、什么时候清、用户从哪里清。缩略图、下载的远程资源、导出中间产物、字体包……凡是「可以随时删掉重建」的文件，都归本方案管。

**一条铁律先行**：缓存与用户数据**目录严格分离**——缓存住系统 cache 目录（OS 磁盘紧张时可能清它、卸载时可以整删它），数据住 data 目录。「清理缓存误删用户数据」是目录混放的事故，结构上杜绝。

**与相邻方案的分工**：一致性级别与 key 纪律 →《缓存一致性方案》（磁盘缓存的 key 同样全输入、L3 内容寻址优先）；目录布局 →《后端目录结构方案》`paths/`；写入原子性与残留清扫 →《应用状态与持久化技术方案》《长任务与后台工作技术方案》；引擎自管的缓存 →《WebView缓存管理方案》。

## 缓存登记表（磁盘卷）

延续母法登记表，磁盘缓存逐项多登三列：

| 缓存 | 目录 | key 方案 | 容量上限 | 清理时机 | 重建成本 |
|---|---|---|---|---|---|
| 例：封面缩略图 | `cache/thumbs/` | `{hash}-{size}.webp` | 500 MB | 容量触发 + 用户手动 | 中（重新生成） |
| 例：下载的字体包 | `cache/fonts/` | 内容寻址 | 50 MB | 随应用更新校验 | 低（重新下载） |

- **key 内容寻址优先**：文件名 = `hash(内容+参数).ext`——同名覆盖天然幂等，无失效问题（L3 纪律的磁盘版）。
- **重建成本列必填**：它决定清理的破坏性（缩略图可静默重建；下载包要重新走网络）。

## 目录与写入纪律

- **只住 `paths/` 分配的 cache 子目录**，一缓存一子目录；文件名即 key，目录内无元数据文件（元数据进内存登记，丢了可重建）。
- **原子写**：临时文件 + 改名（→ 状态方案）；同 key 并发写单飞，半成品不可见。
- **崩溃残留**：写一半被杀 → 临时文件残留——启动清扫（→ 长任务方案崩溃恢复）按「临时前缀/后缀约定」批量删除，clean-up 不需要知道业务。

## 容量治理

- **两级预算**：每缓存自己的上限 + **全部磁盘缓存的总预算**（合计数值写进设计，如 1 GB）——逐个都有上限、加起来吃满磁盘是最常见的翻车。
- **淘汰**：LRU 按**自记的最后访问时间**（文件 atime 不可靠——很多系统默认不更新或延迟更新，依赖它淘汰会失灵）；淘汰批量进行、有节流，不逐访问触发。
- **低盘保护**：写缓存前检查目标卷剩余空间，低于阈值 → 跳过缓存直读源（功能不中断，只是慢）——缓存写失败**绝不允许拖垮主流程**。

## 清理时机与用户入口

- **启动不清理**（冷启动预算 → 性能方案）；清理挂在空闲时机或关闭流程，作为任务可观测（→ 任务队列）。
- **用户入口**：设置页「释放空间」——显示各缓存占用（登记表驱动，数字可信）、一键清理；缓存清理**永远安全**，无需确认弹窗（目录分离是前提）。
- **应用重置 / 卸载**：cache 目录整删（→ 分发方案卸载清理），data 目录按用户意愿。

## 验收清单

- [ ] 登记表驱动：每个磁盘缓存可查目录、上限、清理策略、重建成本
- [ ] 总预算生效：超限按 LRU 淘汰，淘汰后功能正常（重建路径可用）
- [ ] 原子写 + 启动清扫：kill -9 后无半成品残留
- [ ] 低盘模拟：剩余空间不足时跳过缓存、主流程不中断
- [ ] 清理入口：占用数字准确、清理后各功能按重建路径自愈
- [ ] 目录分离审查：cache 目录内无任何用户数据（grep / 演练）
- [ ] atime 不可靠环境（如挂载 noatime）下淘汰仍生效（自记时间戳）

## 常见根因

| 表面现象 | 常见根因 | 开始实现前的预防 |
|---|---|---|
| 磁盘被缓存吃满 | 无总预算、逐缓存上限形同虚设 | 两级预算 + 淘汰 |
| 清理缓存删掉用户数据 | 缓存与数据目录混放 | 目录铁律 + 分离审查 |
| 淘汰从不发生 | 依赖 atime | 自记最后访问时间 |
| 磁盘里全是 .tmp 碎片 | 非原子写、无启动清扫 | 原子写 + 残留清扫 |
| 低盘时应用崩溃 | 缓存写失败未降级 | 剩余空间检查 + 直读源降级 |
| 用户清了缓存占用反而变大 | 清理只清了一类、引擎缓存未含（→ WebView 方案） | 占用统计覆盖全部登记项 |
| 缩略图反复重新生成 | key 缺参数（尺寸变了视为新文件是对的；尺寸没变却 miss 是 key 错） | key 全输入纪律 |

## 给 AI 的实施约束模板

开始实现时，可要求 AI：

> 先给出磁盘缓存登记表（目录 / key / 上限 / 清理时机 / 重建成本）与总预算数值。缓存只住 `paths/` 的 cache 子目录、一缓存一目录、内容寻址命名优先；原子写 + 同 key 单飞 + 启动残留清扫；两级容量预算 + 自记访问时间 LRU + 低盘降级（缓存写失败不拖垮主流程）；清理挂空闲/关闭且作为任务可观测；用户「释放空间」入口数字来自登记表，清理永不含用户数据。实现后跑验收清单，补容量淘汰、残留清扫与低盘降级的测试，并明确列出未覆盖的缓存类型。

方案确认后再改代码；平台 cache 目录行为（系统自动清理时机）随目标平台核实，未验证标注待验证。

## 五档定位

- **一档**：哪些资源落盘缓存 + 登记表初稿 + 总预算决策。
- **二档**：目录纪律、原子写、两级容量治理、清理任务。
- **三 / 四档**：低盘降级全测、用户清理入口、卸载与重置路径。
